`qxctl` ist die Go-basierte, agentisch ausgerichtete Administrations- und Abfrage-CLI von Symphony. Sie spricht Befehle; die Domänenvektoren verantworten die Operationen und Bedeutungen dahinter. Ihre eingecheckte Registry bindet jedes ausführbare Befehls-Leaf an eine stabile Maschinenidentität und an geprüfte Nachweise zur Feature-Administration.

## Was qxctl abdeckt

qxctl implementiert die Administration für:

- Repository- und Vertragsinspektion
- Administration von Validator, Warnungen, Invarianten, Features, Lifecycle, Sessions, Abstimmung, Bindings und Maestro
- SSIAG-Identität, STAV-Audit und Administration von Accordare-Produzenten
- Implementierte Vektor-Engine-Grammatik (`skvi`, `sclv`, `sacv`, `sodv`, `ssfv` sowie SCV- und SHV-Oberflächen)

Die aktuelle Registry enthält **373** ausführbare Befehle.

## Sicheres Aufrufmodell

qxctl ruft exakte, belegvalidierte Installationen über begrenzte Subprozesse, harte Fristen, Prüfungen von Antwortidentität und Digest, Erwartungszustands-Transaktionen und dauerhafte Wiederherstellung auf. Es akzeptiert niemals Adapterpfade oder Rohversionen anstelle von Belegen.

## Engine-Binding-Registry v2

Die Engine-Binding-Registry v2 unterstützt die acht etablierten Engine-Rollen und begrenzte künftige Rollenidentitäten. Legacy-v1-Zustand wird doppelt gelesen; die Migration zu v2 erfordert ein explizites, digest-gebundenes Compare-and-Swap über qxctl und ist niemals eine Versionsauswahl.

## Registry-Befehle

Generieren und verifizieren Sie die erwartete Registry aus `tools/qxctl`:

```bash Registry generation and verification
go run ./cmd/qxctl commands expected --json > COMMANDS.json
go run ./cmd/qxctl commands verify --input COMMANDS.json --json
```

Ein installierter Client kann an die ausführbare Datei gebundene Nachweise ausgeben:

```bash Manifest from installed qxctl
qxctl commands manifest --json
```

Erwartete Nachweise haben eine leere (null) Client-Version, einen leeren Digest der ausführbaren Datei und einen leeren Beleg-Digest. Beobachtete Nachweise binden die exakte Client-Version und den Digest der ausführbaren Datei sowie einen Beleg-Digest, sofern verfügbar. Beide Formen verwenden `symphony.qxctl.command-registry.v1`.

<Note>
  qxctl verantwortet Befehlsgrammatik und Darstellung. Es verantwortet weder Vektorsemantik noch kanonische Wissenswahrheit. Nur geprüfte Quelländerungen ratifizieren eine neue `qxcmd`-Identität, unabhängig von der Aufruferklasse.
</Note>
