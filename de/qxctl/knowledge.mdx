Die Gruppe `qxctl knowledge ...` verantwortet den vektorübergreifenden Lifecycle und die Administration persistenter SSFV-Sessions. Sie ist der Einstiegspunkt für koordinatorgestützte Operationen und für Invarianten-Abfragen gegen den Validator.

## Session-Übergang

Verwenden Sie `qxctl knowledge session transition`, um einer bestehenden Session ein Lifecycle-Ereignis des Hosts zu signalisieren:

```bash Session transition
qxctl knowledge session transition --event login|refresh|logout --event-id ID
```

Sichere Wiederholungen verwenden dieselbe Ereignis-ID erneut. Fügen Sie `--recover` nur hinzu, wenn eine Discovery-Wiederherstellung aus beschädigten lokalen Session-Nachweisen beabsichtigt ist; sie stellt weder Ablehnungen, inkompatiblen kritischen Zustand noch Mehrdeutigkeiten wieder her.

<Warning>
  Symphony installiert über diesen Befehl keinen Login-Hook, Watcher oder keine Boot-Unit. Verwenden Sie ihn nur, wenn eine explizite Host-Lifecycle-Integration eine stabile Ereignisidentität liefert.
</Warning>

## Invarianten-Abfragen

Vier Leaves binden `ssfv:symphony:qxctl.invariant-assurance`:

```bash Invariant queries
qxctl knowledge invariant status
qxctl knowledge invariant list
qxctl knowledge invariant show
qxctl knowledge invariant check
```

`check` bindet zusätzlich `ssfv:symphony:symphony-validator.invariant-ownership-assurance`.

Direkte Abfrage-Leaves geben `symphony.knowledge.invariant-query-result.v1` mit `semantic_validity=not_asserted` aus. `check` liefert das exakte, vollständige Validator-Ergebnis und behält den Exit-Code 26 bei.
