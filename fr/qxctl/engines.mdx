La grammaire `qxctl knowledge engines ...` gère le profil de liaison `default` protégé à l’échelle utilisateur pour les moteurs vectoriels de Symphony. Elle lie un contenu sélectionné en vue d’une réconciliation ultérieure. Elle n’installe, n’invoque, n’active, n’arrime (dock), n’authentifie, n’autorise ni n’applique aucun moteur.

## Commandes

```bash Engines grammar
qxctl knowledge engines list
qxctl knowledge engines inspect
qxctl knowledge engines doctor
qxctl knowledge engines bind    --expected-registry-digest absent|DIGEST ...
qxctl knowledge engines unbind  --expected-registry-digest DIGEST ...
qxctl knowledge engines migrate --expected-registry-digest DIGEST ...
```

Fournissez `absent` pour la première mutation du registre v2, ou le digest exact signalé par `list` pour les mutations suivantes. Chaque mutation est un compare-and-swap par rapport à ce digest.

## Migration de v1 vers v2

<Warning>
  Un état de registre v1 valide reste lisible. La migration vers v2 est un compare-and-swap exact distinct et n’est jamais une opération de sélection de version. Ne considérez pas la migration comme un chemin de mise à niveau pour la sélection de moteurs.
</Warning>

- `list` et `inspect` continuent de fonctionner sur les preuves v1.
- `migrate` produit une génération v2 liée sans écarter la vérité v1.
- Après la migration, utilisez les digests v2 pour les mutations futures.

## Ce qu’est une liaison

Une liaison sélectionne un contenu exact en vue d’une réconciliation ultérieure par le coordinateur. Elle :

- N’installe pas de moteur
- N’invoque ni n’active de moteur
- N’arrime pas de moteur auprès de Maestro
- N’authentifie pas d’appelant
- N’autorise pas l’application (apply)
