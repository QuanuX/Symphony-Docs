Le groupe `qxctl knowledge ...` gère le cycle de vie inter-vecteurs et l’administration des sessions SSFV persistantes. C’est le point d’entrée des opérations adossées au coordinateur et des requêtes d’invariants auprès du validateur.

## Transition de session

Utilisez `qxctl knowledge session transition` pour signaler un événement de cycle de vie de l’hôte à une session existante :

```bash Session transition
qxctl knowledge session transition --event login|refresh|logout --event-id ID
```

Les nouvelles tentatives sûres réutilisent le même identifiant d’événement. N’ajoutez `--recover` que lorsqu’une récupération par découverte à partir de preuves de session locales endommagées est souhaitée ; cela ne récupère ni un refus, ni un état critique incompatible, ni une ambiguïté.

<Warning>
  Symphony n’installe aucun hook de connexion, observateur ou unité de démarrage via cette commande. Utilisez-la uniquement lorsqu’une intégration explicite du cycle de vie de l’hôte fournit une identité d’événement stable.
</Warning>

## Requêtes d’invariants

Quatre feuilles lient `ssfv:symphony:qxctl.invariant-assurance` :

```bash Invariant queries
qxctl knowledge invariant status
qxctl knowledge invariant list
qxctl knowledge invariant show
qxctl knowledge invariant check
```

`check` lie en outre `ssfv:symphony:symphony-validator.invariant-ownership-assurance`.

Les feuilles de requête directe émettent `symphony.knowledge.invariant-query-result.v1` avec `semantic_validity=not_asserted`. `check` renvoie le résultat complet et exact du validateur et conserve le code de sortie 26.
