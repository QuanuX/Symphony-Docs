`qxctl` هو واجهة سطر الأوامر الإدارية والاستعلامية في Symphony، المبنية بلغة Go والمصممة للوكلاء أولًا. هو يتحدث بالأوامر؛ أما متجهات النطاق فتملك العمليات والمعاني التي تقف خلفها. ويربط سجله المحفوظ في المستودع كل أمر تنفيذي نهائي بهوية آلية مستقرة وبأدلة إدارة ميزات تمت مراجعتها.

## ما يغطيه qxctl

ينفّذ qxctl الإدارة لما يلي:

- فحص المستودع والعقود
- إدارة المدقق والتحذيرات والثوابت والميزات ودورة الحياة والجلسات والتسوية والربط وMaestro
- إدارة هوية SSIAG وتدقيق STAV ومنتِج Accordare
- قواعد أوامر محركات المتجهات المنفذة (`skvi` و`sclv` و`sacv` و`sodv` و`ssfv`، إضافةً إلى واجهات SCV وSHV)

يحتوي السجل الحالي على **373** أمرًا تنفيذيًا.

## نموذج الاستدعاء الآمن

يستدعي qxctl تثبيتات دقيقة موثّقة بالإيصالات باستخدام عمليات فرعية محدودة، ومهل نهائية صارمة، وفحوص لهوية الاستجابة وملخصها، ومعاملات الحالة المتوقعة، والاسترداد الدائم. ولا يقبل أبدًا مسارات المحوّلات أو الإصدارات الخام بدلًا من الإيصالات.

## سجل ربط المحركات v2

يدعم سجل ربط المحركات v2 أدوار المحركات الثمانية المعتمدة وهويات أدوار مستقبلية محدودة. تُقرأ حالة v1 القديمة قراءة مزدوجة؛ ويتطلب الترحيل إلى v2 عملية مقارنة ومبادلة صريحة مقيدة بالملخص عبر qxctl، وليس أبدًا عملية لاختيار الإصدار.

## أوامر السجل

أنشئ السجل المتوقع وتحقق منه من `tools/qxctl`:

```bash Registry generation and verification
go run ./cmd/qxctl commands expected --json > COMMANDS.json
go run ./cmd/qxctl commands verify --input COMMANDS.json --json
```

يمكن للعميل المثبّت إصدار أدلة مرتبطة بالملف التنفيذي:

```bash Manifest from installed qxctl
qxctl commands manifest --json
```

تحتوي الأدلة المتوقعة على قيم فارغة لإصدار العميل وملخص الملف التنفيذي وملخص الإيصال. أما الأدلة المرصودة فتربط إصدار العميل الدقيق وملخص الملف التنفيذي، إضافةً إلى ملخص الإيصال عند توفره. يستخدم كلا الشكلين `symphony.qxctl.command-registry.v1`.

<Note>
  يملك qxctl قواعد الأوامر وطريقة عرضها، لكنه لا يملك دلالات المتجهات ولا حقيقة المعرفة القانونية. وحدها تغييرات المصدر التي تمت مراجعتها تُقرّ هوية `qxcmd` جديدة، بغض النظر عن فئة المستدعي.
</Note>
