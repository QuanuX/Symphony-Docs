Gramatika `qxctl knowledge session ...` otevírá nekanonické autentizované relace prostřednictvím jednoho přesně vázaného koordinátoru a jednoho koncového bodu SSIAG v rozsahu TOPS. Samostatná gramatika `session features ...` řídí perzistentní proud údržby SSFV.

## Základní gramatika relací

```bash Session lifecycle
qxctl knowledge session begin
qxctl knowledge session status
qxctl knowledge session checkpoint
qxctl knowledge session close
qxctl knowledge session recover
```

Každé volání si vyžádá nový přesný grant a ověřuje:

- Identitu subjektu a cíle
- Stav politiky a konfigurace
- Expiraci
- Neutralitu vůči třídě volajícího
- Nepřenositelnost
- Zakázání kanonického apply
- Vazbu schopností

Důkazy relace autorizují pouze pojmenovanou chráněnou nekanonickou operaci. Žurnály relací a rekonciliace udržujte oddělené; k jejich přiřazení používejte pouze kontextové odkazy.

## Proud údržby SSFV

```bash Features stream
qxctl knowledge session features begin
qxctl knowledge session features status
qxctl knowledge session features checkpoint
qxctl knowledge session features close
qxctl knowledge session features recover
```

Proud features je samostatný perzistentní kontext údržby SSFV. Mutace vyžadují:

- Otevřenou autentizovanou základní relaci
- Přesné vazby koordinátoru a SSFV
- Stabilní identifikátory operací
- Přesný compare-and-swap
- Nové důkazy SSIAG

<Note>
  Zachovejte základní snímek a jeho původní identitu enginu napříč kompatibilními upgrady a rollbacky. Volitelné důkazy z Maestra musí představovat úplný autentizovaný inventář; pokud Maestro záměrně chybí, zaznamenejte explicitní důvod „not-configured“. `review_required` je důkaz pro kontrolu volajícím, nikoli ratifikace.
</Note>
