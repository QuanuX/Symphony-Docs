Symphony は、ユーザーが選択するインフラストラクチャとワークロードを、プラットフォームのナレッジおよび管理から分離します。プラットフォームは、あなたの戦略の所有権を主張したり推奨を義務として扱ったりすることなく、互換性を検査、検証、報告できます。

## 物理層とワークロード層

[Node](/jp/concepts/node-habitat-nest) は識別された物理コンピューターです。**Habitat** はその厳密なオペレーティングシステムとパッケージの構成であり、**Nest** はあなたが選択した目的を果たすワークロードです。クラスターは 1 つ以上のバスを通じて Node を接続します。バスファブリック、アダプター、プロバイダー、ハードウェアの選択は、普遍的なデフォルトではなく明示的なものです。

[ホットパス](/jp/concepts/hot-path-isolation) は管理系の常駐から分離されたままです。qxctl とナレッジプレーンの作業は Node を明示的に管理できますが、ライブ実行の隠れた継続的依存になることはありません。

## セマンティック所有

[Vector](/jp/concepts/vectors) は、意味と許可された操作を所有する、境界づけられた永続的なオーナーです。各オーナーは Contract Quad を公開します: `INTENT.md`、`MANIFEST.md`、`SKILL.md`、`SPEC.md`。[Symphony Knowledge Vector (SKV)](/jp/skv/overview) は正規のサーフェスをインデックス化し、そのオーナーへのルートを保持します。コンパニオンのスキーマ、レジストリ、台帳は、Quad の追加メンバーになることなく管理対象のままです。

配信フェーズは、作業がいつ行われるかを記述します。セマンティック所有をある vector から別の vector へ移すものではありません。

## エンジンとコマンドサーフェス

[Vector エンジン](/jp/engines/overview) は、個別にインストール可能なプロセス外のコンポーネントで、オーナーコントラクトの範囲内で検査、チェック、プロジェクション、提案を行います。提案を生成したというだけで権限を得ることはありません。

[qxctl](/jp/qxctl/overview) は管理コマンドの文法と表示を所有します。範囲が限定され、レシートで検証された機能を呼び出しますが、操作を定義する vector がそのセマンティクスを保持します。変更を伴うルートは認可と監査のエビデンスによって管理されます。[呼び出し元の分類](/jp/concepts/caller-authority) だけでは権限は付与されません。

## 真実と進化

現在のコントラクトは現在の真実を示します。変更台帳と公開台帳は、特定の時点で記録されたエビデンスを保持します。コントラクト、実装のエビデンス、記録された履歴の間の食い違いは、黙って書き換えられるのではなく、ドリフトとして提示されます。[SAV](/jp/skv/sav) は合成の互換性を評価し、[SEV](/jp/skv/sev) は管理された進化を計画します。

<Note>
  この概要は境界の地図です。特定のインストールで機能が利用可能であるとみなす前に、リンク先の各 vector の現在のコントラクトと実装のエビデンスを確認してください。
</Note>
