Symphony のアーキテクチャは 2 つの考え方を軸に構成されています。**vector** は永続的なセマンティック所有ドメインであり、**フェーズ** は時系列の配信キャンペーンです。あるフェーズで最初に調査されたコンポーネントであっても、そのフェーズが恒久的なオーナーになるわけではありません。vector は、実装が進化しても意味を安定させます。

## vector とは

vector は、永続的で境界づけられたセマンティック所有ドメインであり、その正規のコントラクトがドメインの意味と許可された操作を所有します。各 vector は **Contract Quad** を受け取ります: `INTENT.md`、`MANIFEST.md`、`SKILL.md`、`SPEC.md`、および実際に必要となる焦点を絞ったコンパニオンサーフェスです。vector は自身の正規サーフェスと委任グラフを宣言し、SKVI は現在の各サーフェスを正確に 1 回マッピングします。廃止されたコンパニオンは、矛盾するコンテキストとして残り続けるのではなく、管理された進化を通じて置き換えられます。

## Contract Quad とコンパニオンサーフェス

すべての vector は次のものを受け取ります:

1. **INTENT.md** — 目的と範囲
2. **MANIFEST.md** — アイデンティティ、宣言されたサーフェス、委任グラフ
3. **SKILL.md** — 安全な使用方法と運用ガイダンス
4. **SPEC.md** — 規範的な動作と境界

`SLANG.md`、`NAMESPACES.md`、レジストリ、スキーマ、プロファイルなどのコンパニオンサーフェスは、4 つのメンバーからなる構造の外にある管理対象の成果物です。これらはオーナーの真実をルーティングまたは特化しますが、自らの権限を拡大することはできません。

## エビデンスに基づく統合

延期されたエンジンには捏造されたレシートはありません。提案中の API には架空のレジストリエントリはありません。未公開のコントラクトには SODV の完了の主張はありません。これは形式的な重複ではなく、エビデンスに基づく統合です。
