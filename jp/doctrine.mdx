Symphony のドクトリンは、プラットフォームが管理するものとあなたが管理するものの境界を定義します。これらのルールは、モノレポにおけるすべての設計判断と、qxctl、vector エンジン、ナレッジコントラクトとのすべてのやり取りを規定します。

## ユーザー所有

戦略ロジック、Nest の目的、プロバイダーの選択、ハードウェアの選択、バストポロジー、サポートされるアダプターの選択は、あなたが所有します。Symphony は厳密な互換性のエビデンスとサポートされる操作を提供しますが、推奨をプラットフォームの規則に変えることはありません。プラットフォームは一致、不一致、未解決の事実、およびその影響を報告します。プロバイダーをランク付けしたり、戦略を指示したり、あなたの環境を黙って拡張したりすることはありません。

## ホットパスの保護

ホットパスは、管理系の常駐や偶発的な共有バスへの負荷から保護されます。qxctl とナレッジプレーンは、コールドパスまたはフリージングパスの管理です。ライブ処理もホストしている Node に対して明示的に操作することはできますが、継続的なホットパス依存、隠れたウォッチャー、常駐インタープリター、要求されていないバックグラウンドのパッケージマネージャーになってはなりません。あなたが明示したアーキテクチャが常に優先されます。

## コマンドとセマンティクスの分離

qxctl はコマンドの文法と表示を所有します。ドメインの vector は、それらのコマンドが公開する操作と意味を所有します。qxctl のルートは、オーナーが定義した機能を、そのセマンティクスを取り込むことなく呼び出します。

## 名前と名前空間

名前は、それを所有するスコープの下で記録されます。SNV と SCNV が名前を指示することはなく、ルートの NAMESPACES は SNV よりも広い範囲を持ちます。TOPS または TROG 内で登録された名前は、そのスコープに従います。複数のクラスターにまたがる場合、Node の短縮名は異なるクラスターで重複してもかまいませんが、同じクラスター内の 2 つのアクティブな Node を曖昧に識別してはなりません。

## 呼び出し元クラスの中立性

呼び出し元が人間、AI、エージェント、サービス、ワークロードのいずれに分類されるかによって、権限が付与されたり取り消されたりすることはありません。サポートされる認可判断は、ターゲットホストの所有権または付与された権限、要求された操作とリソース、期待される状態、オーナーが設定したセーフガードを用います。ターゲットホストの管理者は、設定可能なガバナンスに対して最終的な権限を持ちます。SSIAG は有効なホスト権限を検証・投影できますが、上位の登録機関を作り出すことはありません。強化されたアイデンティティ保証とガバナンスインターロックは、呼び出し元に中立な、オーナーが設定するセーフガードです。プロトコル完全性の要件は引き続き必須です。Symphony は、呼び出し元の種類によって外部の法的または財務的な能力を判断しません。

## 真実とエビデンス

現在のコントラクトは現在の真実を記述します。不変の SCLV および SODV のレコードは、記録された履歴上の時点で何が知られ、変更され、認可され、完了したかを保持します。現在のコントラクト、実装のエビデンス、適用される最新のレコードが食い違う場合、その食い違いはレビューのためにドリフトとして提示されます。履歴が現在に合わせて黙って書き換えられることはありません。

## Python ドクトリン

ファーストパーティの Symphony のソース、ジェネレーター、スキーマ作成、テスト、受け入れヘルパーは、Python の実装やインタープリターへの依存を必要としません。置き換えとなる作成ツールとプロセステストのツールは C++ が担います。このリポジトリポリシーは、あなたが作成したプログラムや、明示的に選択した分離された Habitat を制限するものではありません。
