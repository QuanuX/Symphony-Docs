`qxctl` — це агентно-орієнтований адміністративний і запитовий CLI Symphony на основі Go. Він оперує командами; доменні вектори володіють операціями та значеннями, що стоять за ними. Його зафіксований у репозиторії реєстр прив’язує кожну виконувану листову команду до стабільної машинної ідентичності та перевірених доказів адміністрування функцій.

## Що охоплює qxctl

qxctl реалізує адміністрування для:

- Перевірки репозиторію та контрактів
- Адміністрування валідатора, попереджень, інваріантів, функцій, життєвого циклу, сесій, узгодження, прив’язок і Maestro
- Адміністрування ідентичності SSIAG, аудиту STAV і продюсерів Accordare
- Граматики реалізованих векторних рушіїв (`skvi`, `sclv`, `sacv`, `sodv`, `ssfv`, а також поверхні SCV і SHV)

Поточний реєстр містить **373** виконувані команди.

## Безпечна модель виклику

qxctl викликає точні інсталяції, перевірені квитанціями, використовуючи обмежені підпроцеси, жорсткі дедлайни, перевірки ідентичності та дайджесту відповіді, транзакції очікуваного стану й довговічне відновлення. Він ніколи не приймає шляхи адаптерів чи сирі версії замість квитанцій.

## Реєстр прив’язок рушіїв v2

Реєстр прив’язок рушіїв v2 підтримує вісім усталених ролей рушіїв та обмежені майбутні ідентичності ролей. Застарілий стан v1 читається паралельно; міграція на v2 вимагає явного compare-and-swap, прив’язаного до дайджесту, через qxctl і ніколи не є операцією вибору версії.

## Команди реєстру

Згенеруйте та перевірте очікуваний реєстр із `tools/qxctl`:

```bash Registry generation and verification
go run ./cmd/qxctl commands expected --json > COMMANDS.json
go run ./cmd/qxctl commands verify --input COMMANDS.json --json
```

Встановлений клієнт може видавати докази, прив’язані до виконуваного файлу:

```bash Manifest from installed qxctl
qxctl commands manifest --json
```

Очікувані докази мають порожні (null) версію клієнта, дайджест виконуваного файлу та дайджест квитанції. Спостережувані докази прив’язують точну версію клієнта й дайджест виконуваного файлу, а також дайджест квитанції, якщо він доступний. Обидві форми використовують `symphony.qxctl.command-registry.v1`.

<Note>
  qxctl володіє граматикою команд і їх поданням. Він не володіє семантикою векторів чи канонічною істиною знань. Лише перевірені зміни вихідного коду ратифікують нову ідентичність `qxcmd`, незалежно від класу викликача.
</Note>
