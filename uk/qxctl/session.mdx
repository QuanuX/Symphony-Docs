Граматика `qxctl knowledge session ...` відкриває неканонічні автентифіковані сесії через один точний прив’язаний координатор і одну кінцеву точку SSIAG з областю дії TOPS. Окрема граматика `session features ...` керує постійним потоком обслуговування SSFV.

## Базова граматика сесій

```bash Session lifecycle
qxctl knowledge session begin
qxctl knowledge session status
qxctl knowledge session checkpoint
qxctl knowledge session close
qxctl knowledge session recover
```

Кожен виклик запитує свіжий точний дозвіл і перевіряє:

- Ідентичність суб’єкта та цілі
- Стан політики та конфігурації
- Термін дії
- Нейтральність щодо класу викликача
- Непередаваність
- Вимкнення канонічного застосування
- Прив’язку можливостей

Докази сесії авторизують лише названу захищену неканонічну операцію. Тримайте журнали сесій і узгодження окремо; використовуйте посилання на контекст лише для їх пов’язування.

## Потік обслуговування SSFV

```bash Features stream
qxctl knowledge session features begin
qxctl knowledge session features status
qxctl knowledge session features checkpoint
qxctl knowledge session features close
qxctl knowledge session features recover
```

Потік функцій — це окремий постійний контекст обслуговування SSFV. Мутації вимагають:

- Відкритої автентифікованої базової сесії
- Точних прив’язок координатора та SSFV
- Стабільних ідентифікаторів операцій
- Точного compare-and-swap
- Свіжих доказів SSIAG

<Note>
  Зберігайте базовий знімок і його початкову ідентичність рушія під час сумісних оновлень або відкатів. Необов’язкові докази Maestro мають бути повним автентифікованим інвентарем; коли Maestro навмисно відсутній, зафіксуйте явну причину відсутності налаштування. `review_required` — це доказ для перегляду викликачем, а не ратифікація.
</Note>
