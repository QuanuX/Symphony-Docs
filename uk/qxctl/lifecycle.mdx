Граматика `qxctl knowledge lifecycle ...` адмініструє захищені профілі, володіння, спостереження, журнали завантаження та сумісні із застосуванням переходи. Кожна мутація виконується як compare-and-swap, а кожне застосування прив’язане до точних доказів.

## Профіль

Встановіть захищений профіль життєвого циклу для TOPS:

```bash Profile compare-and-swap
qxctl knowledge lifecycle profile set \
  --tops-id UUID \
  --input FILE \
  --expected-profile-digest absent|DIGEST
```

Передайте `absent` для профілю, що створюється вперше, або точний дайджест, повідомлений попереднім читанням.

## Володіння

- `ownership status`: перевірити один налаштований спільний корінь
- `ownership reconcile`: оновити його докази
- `ownership adopt`: перейняти лише після перегляду кожної консервативної застарілої заявки
- `ownership release`: звільнити лише для однієї точної застарілої квитанції, яку навмисно зроблено доступною для повторного заявлення

<Warning>
  Ніколи не видаляйте й не переписуйте вручну локальний для кореня реєстр або його бар’єр сумісності формату квитанцій `symphony-root-ownership/1`. Старіші клієнти життєвого циклу мають натрапити на цей бар’єр і зупинитися на своєму наявному блокувальнику невідомого пакета.
</Warning>

## Спостереження, звіт, завантаження

- `observe`: видати одноразові докази квитанцій із фіксованим форматом
- `report`: створити свіжий одноразовий план
- `boot`: довговічне просування лише у форматі звіту зі стабільним ідентифікатором операції та точним станом журналу
- `status`: перевірка v1
- `recover --discover`: відновити унікальний ланцюжок v1, коли звичайний статус не може перевірити локальний стан

## Профілі, сумісні із застосуванням

Для профілю `apply-compatible` викликайте `apply` лише з точним дайджестом джерела завантаження, compare-and-swap журналу застосування, compare-and-swap застосованого стану, стабільним ідентифікатором операції та явно вказаними підготовленими коренями:

```bash Apply
qxctl knowledge lifecycle apply \
  --tops-id UUID \
  --operation-id OPID \
  --boot-source-digest DIGEST \
  --expected-apply-journal-digest DIGEST \
  --expected-applied-state-digest DIGEST \
  --staged-root PATH
```

Використовуйте `apply-status` для спостереження за спробою або обмежену `apply-recover` для довговічного відновлення. Ніколи не обирайте дію вручну і не редагуйте захищений стан.

<Note>
  Оновлення спостереження, що змінює лише позначку часу, має змінювати докази документа, не просуваючи стабільні семантичні ідентичності.
</Note>
