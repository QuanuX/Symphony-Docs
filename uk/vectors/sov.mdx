Symphony Ops Vector (SOV) — це операційна площина керування, через яку авторизовані команди qxctl діють на вашу інфраструктуру. Він володіє контрактом для розгортання, підготовки Habitat (середовища), доставки Nest (гнізда робочих навантажень), налаштування адаптерів шини та необов’язкового віддаленого адміністрування Node. SOV не вигадує значень провайдерів чи апаратних фактів; він виконує підтримувані варіанти, які ви вже обрали.

## Що охоплює SOV

SOV — це новий домен Фази 2. Його обсяг включає:

- **Розгортання**: робочі процеси розподілу ресурсів провайдерів і власного обладнання
- **Підготовка Habitat**: точна підготовка ОС і пакетів, що доставляється на Node
- **Доставка Nest**: розміщення та оновлення робочих навантажень на Node
- **Встановлення адаптера шини**: з’єднання Node через обрану вами шину (NATS JetStream, ZeroMQ чи інші)
- **Віддалені операції з Node**: необов’язкове адміністрування Node за межами вашої локальної оболонки

<Note>
  Протоколи провайдерів, виконання Terraform, збирачі Habitat, команди розгортання Nest і приймачі віддалених операцій ще мають бути спроєктовані. Наразі не реалізовано жодного рушія SOV чи мутації провайдера.
</Note>

## qxctl як командна поверхня

Операції SOV надаються через `qxctl` — адміністративний CLI на основі Go з 373 виконуваними командами. qxctl реалізує та подає операції SOV, але не володіє їхнім доменним значенням. Вектор володіє семантикою; інструмент володіє поверхнею виконання.

## Межа повноважень користувача

Ви обираєте провайдерів, регіони, обладнання, шини, програмне забезпечення, топологію розгортання та схеми адміністрування для кожного Node. SOV надає та виконує підтримувані варіанти. Він не ранжує провайдерів, не рекомендує топології й не перетворює пропозиції на обов’язкову політику.

## Поточний статус

SOV — це канонічний архітектурний контракт. Жоден рушій, обгортка Terraform, збирач Habitat, адаптер шини чи приймач віддалених команд не заявлено як реалізований. Майбутні компоненти SOV залишатимуться незалежно встановлюваними, з можливістю вибору точної версії та відкату в межах спільного життєвого циклу SKV.
