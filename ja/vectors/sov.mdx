Symphony Ops Vector（SOV）は、認可された qxctl コマンドがインフラストラクチャに対して動作する際の運用コントロールプレーンです。プロビジョニング、Habitat の調整、Nest の配信、バスアダプターのセットアップ、オプションのリモート Node 管理のコントラクトを所有します。SOV がプロバイダーの意味やハードウェアの事実を作り出すことはなく、あなたがすでに選択したサポート対象の選択肢を実行します。

## SOV がカバーする範囲

SOV は新興の Phase 2 ドメインです。そのスコープには次のものが含まれます。

- **プロビジョニング**: プロバイダーおよび所有ハードウェアのリソース割り当てワークフロー
- **Habitat の調整**: Node に配信される正確な OS とパッケージの調整
- **Nest の配信**: Node 上のワークロードの配置と更新
- **バスアダプターの確立**: 選択したバス（NATS JetStream、ZeroMQ など）を通じた Node の接続
- **リモート Node の操作**: ローカルシェルの外にある Node のオプションの管理

<Note>
  プロバイダープロトコル、Terraform の実行、Habitat ビルダー、Nest のデプロイコマンド、リモート操作のレシーバーは、これから設計される予定です。SOV エンジンやプロバイダーの変更は、現在いずれも実装されていません。
</Note>

SOV はコントロールプレーンであり、知識のソースではありません。他のベクトルが所有するエビデンスに基づいて動作します。

## コマンドサーフェスとしての qxctl

SOV の操作は、373 の実行可能コマンドを持つ Go ベースの管理 CLI である `qxctl` を通じて公開されます。qxctl は SOV の操作を実装・提示しますが、そのドメイン上の意味は所有しません。セマンティクスはベクトルが所有し、実行サーフェスはツールが所有します。

## ユーザーのオーソリティの境界

プロバイダー、リージョン、ハードウェア、バス、ソフトウェア、デプロイトポロジー、Node ごとの管理の取り決めは、あなたが選択します。SOV はサポート対象の選択肢を公開し、実行します。プロバイダーを順位付けしたり、トポロジーを推奨したり、提案を必須のポリシーに変えたりすることはありません。

## 現在のステータス

SOV は正規のアーキテクチャコントラクトです。エンジン、Terraform ラッパー、Habitat ビルダー、バスアダプター、リモートコマンドレシーバーのいずれも、実装済みとはされていません。将来の SOV コンポーネントは、共通の SKV ライフサイクルの下で、引き続き個別にインストール可能で、正確なバージョンを選択でき、ロールバック可能なものになります。
