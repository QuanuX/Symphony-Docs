Symphony ドクトリンは、プラットフォームが制御するものとあなたが制御するものの境界を定義します。これらのルールは、モノレポにおけるあらゆる設計判断と、qxctl、ベクターエンジン、ナレッジコントラクトとのあらゆるやり取りを規定します。

## ユーザー所有

戦略ロジック、Nest の目的、プロバイダーの選択、ハードウェアの選択、バストポロジー、サポートされるアダプターの選択は、あなたが所有します。Symphony は正確な互換性のエビデンスとサポートされる操作を提供しますが、推奨をプラットフォームの規則に変えることはありません。プラットフォームは、一致、不一致、未解決の事実、およびその結果を報告します。プロバイダーをランク付けしたり、戦略を規定したり、あなたの環境を黙って拡張したりすることはありません。

## ホットパスの保護

ホットパスは、管理用コンポーネントの常駐や、意図しない共有バスへの負荷から保護されます。qxctl とナレッジプレーンは、コールドパスまたはフリージングパスの管理機能です。ライブ処理もホストしている Node に対して明示的に操作することはできますが、継続的なホットパスの依存関係、隠れたウォッチャー、常駐インタープリター、または頼まれていないバックグラウンドのパッケージマネージャーになってはなりません。あなたが明示したアーキテクチャが常に最優先されます。

## コマンドとセマンティクスの分離

qxctl はコマンドの文法と表示を所有します。ドメインベクターは、それらのコマンドが公開する操作と意味を所有します。qxctl のルートは、オーナーが定義した機能を、そのセマンティクスを取り込むことなく呼び出します。

## 名前と名前空間

名前は、それを所有するスコープの下に記録されます。SNV と SCNV が名前を決めることはなく、ルートの NAMESPACES は SNV よりも広い範囲を持ちます。TOPS または TROG 内で登録された名前は、そのスコープに従います。複数のクラスターにまたがる場合、Node の短縮名は異なるクラスターで重複しても構いませんが、同じクラスター内の 2 つのアクティブな Node を曖昧に指してはなりません。

## 呼び出し元クラスの中立性

呼び出し元が人間、AI、エージェント、サービス、ワークロードのいずれに分類されるかによって、権限が付与されたり剥奪されたりすることはありません。サポートされる認可判断では、ターゲットホストの所有権または付与された権限、要求された操作とリソース、期待される状態、オーナーが構成したセーフガードを使用します。ターゲットホストの管理者は、構成可能なガバナンスに対して最終的な権限を持ちます。SSIAG は有効なホスト権限を検証および投影できますが、より上位の登録機関を作り出すことはありません。強化されたアイデンティティ保証とガバナンスのインターロックは、呼び出し元に中立な、オーナーが構成するセーフガードです。プロトコル整合性の要件は引き続き必須です。Symphony は、外部の法的または財務的な能力を呼び出し元の種類によって判断しません。

## 真実とエビデンス

現在のコントラクトは現在の真実を記述します。不変の SCLV および SODV のレコードは、記録された時点で何が知られ、変更され、認可され、完了したかを保存します。現在のコントラクト、実装のエビデンス、および適用される最新のレコードが一致しない場合、その不一致はレビューのためにドリフトとして提示されます。履歴が現在に合わせて黙って書き換えられることはありません。

## Python ドクトリン

ファーストパーティの Symphony ソース、ジェネレーター、スキーマのオーサリング、テスト、受け入れヘルパーは、Python の実装やインタープリターへの依存を必要としません。代替となるオーサリングツールとプロセステストツールは C++ が担います。このリポジトリポリシーは、あなたが作成したプログラムや、明示的に選択した分離された Habitat を制限するものではありません。
