Symphony は、ハードウェアのアイデンティティ、ソフトウェアのコンディショニング、ユーザーのワークロードを分離する 3 つの物理的な概念を定義しています。これらの概念によってインフラストラクチャ上の関心事が区別されるため、それぞれを独立して考えることができます。

## Node

**Node** は、具体的に識別されたリソースを持つ、ターゲットとなる物理的なコンピューターリソースです。切断、再接続、再起動、またはソフトウェアのみの再フラッシュでは、新しい物理 Node は作成されません。破壊、物理的な交換、または重要なローカルハードウェアの変更があった場合は、新しい Node になります。Node インカネーションは、その Node がトレーディングシステム、リサーチクラスター、または Symphony で構築された他のシステムの参加者としてバスに接続されたときに作成される、別個のエビデンスです。

## Habitat

**Habitat** は、あなたが選択した作業のために Node に提供される、正確なオペレーティングシステムとパッケージのコンディショニングです。デフォルトでは必要なソフトウェアサーフェスのみで構成され、無関係なパッケージ、隠れたランタイム、コンテナー、Kubernetes、暗黙の仮想化は含まれません。幅広い汎用的な Habitat も、ユーザーによる明示的な選択として有効です。

## Nest

**Nest** は、あなたが選んだ目的を果たします。ライブ戦略の実行が一般的な用途になると想定されており、1 つの戦略に多数のモジュール式コードセクションが含まれることもあります。Symphony は Nest の目的を定義せず、それを 1 つのソースファイル、プロセス、アルゴリズム、ブローカー API、またはデータインターフェースと同一視することもありません。戦略ロジックはあなたの領域です。

## 比較

| 概念 | 内容 | 変更の契機 |
| --- | --- | --- |
| **Node** | 特定のリソースを持つ物理コンピューター | 物理的な破壊、交換、または重要なハードウェアの変更 |
| **Habitat** | Node 上の正確な OS とパッケージのコンディショニング | ユーザーによる明示的な選択、または qxctl が管理するコンディショニング |
| **Nest** | Habitat に配置されるユーザー目的のワークロード | ユーザーによる戦略やその他の選択した作業のデプロイ |

## クラスターとバストポロジー

複数の Node は、1 つ以上のバスを通じて互いに接続されている場合にのみクラスターを形成します。1 つのクラスター内に複数のバスファブリックが共存することもあり、Node とクラスターの関係では、物理 Node のアイデンティティを変えることなく、関連するバスを識別できます。

NATS JetStream や ZeroMQ などのバスアダプターはユーザーが選択するものであり、ドクトリンではありません。大量転送、制御、リサーチ、実行の排出データは、1 つのバスを共有する必要はありません。トポロジーでは、複数のバスを使用したり、宣言されたパスでバスを経由しないようにしたりできます。

## TOPS と TROG のスコープ

**TOPS** は、支配的な Trade Operating System のスコープです。**TROG** は、意図的に従属させた、グローバルではないトレーディンググループのスコープです。歴史的な名称に反して、TROG は必ずしも仮想的なものではありません。その特徴は、スコープとルールが普遍的ではないことです。
