A gramática `qxctl knowledge lifecycle ...` administra perfis protegidos, propriedade, observações, journals de boot e transições compatíveis com apply. Toda mutação é um compare-and-swap e todo apply está vinculado a evidências exatas.

## Perfil

Defina o perfil de ciclo de vida protegido para um TOPS:

```bash Profile compare-and-swap
qxctl knowledge lifecycle profile set \
  --tops-id UUID \
  --input FILE \
  --expected-profile-digest absent|DIGEST
```

Informe `absent` para um perfil criado pela primeira vez ou o digest exato relatado por uma leitura anterior.

## Propriedade

- `ownership status`: inspeciona uma raiz compartilhada configurada
- `ownership reconcile`: atualiza suas evidências
- `ownership adopt`: adota somente após revisar cada reivindicação legada conservadora
- `ownership release`: libera somente para um recibo legado exato tornado intencionalmente reivindicável

<Warning>
  Nunca exclua nem reescreva manualmente o registro local da raiz ou a sua barreira de compatibilidade de layout de recibos `symphony-root-ownership/1`. Clientes de ciclo de vida mais antigos precisam encontrar essa barreira e parar no bloqueio de pacote desconhecido já existente.
</Warning>

## Observar, relatar, boot

- `observe`: emite evidências descartáveis de recibo com layout fixo
- `report`: produz um plano descartável novo
- `boot`: progressão durável somente de relatório, com um ID de operação estável e estado exato do journal
- `status`: inspeção v1
- `recover --discover`: recupera uma cadeia v1 única quando o status comum não consegue validar o estado local

## Perfis compatíveis com apply

Para um perfil `apply-compatible`, chame `apply` somente com o digest exato da origem do boot, o compare-and-swap do journal de apply, o compare-and-swap do estado aplicado, um ID de operação estável e raízes preparadas explícitas:

```bash Apply
qxctl knowledge lifecycle apply \
  --tops-id UUID \
  --operation-id OPID \
  --boot-source-digest DIGEST \
  --expected-apply-journal-digest DIGEST \
  --expected-applied-state-digest DIGEST \
  --staged-root PATH
```

Use `apply-status` para observar tentativas ou o `apply-recover` delimitado para recuperação durável. Nunca escolha uma ação manualmente nem edite o estado protegido.

<Note>
  Uma atualização de observação que altere apenas o timestamp deve modificar as evidências do documento sem avançar as identidades semânticas estáveis.
</Note>
