Gramatyka `qxctl knowledge session ...` otwiera niekanoniczne, uwierzytelnione sesje za pośrednictwem jednego dokładnie powiązanego koordynatora i jednego punktu końcowego SSIAG o zakresie TOPS. Oddzielna gramatyka `session features ...` steruje trwałym strumieniem utrzymania SSFV.

## Podstawowa gramatyka sesji

```bash Session lifecycle
qxctl knowledge session begin
qxctl knowledge session status
qxctl knowledge session checkpoint
qxctl knowledge session close
qxctl knowledge session recover
```

Każde wywołanie żąda świeżego, dokładnego uprawnienia (grant) i weryfikuje:

- Tożsamość podmiotu i celu
- Stan polityki i konfiguracji
- Wygaśnięcie
- Neutralność względem klasy wywołującego
- Nieprzenoszalność
- Wyłączenie kanonicznego apply
- Powiązanie z uprawnieniem (capability)

Dowody sesji autoryzują wyłącznie nazwaną, chronioną operację niekanoniczną. Utrzymuj dzienniki sesji i rekoncyliacji oddzielnie; do ich powiązania używaj wyłącznie odwołań do kontekstu.

## Strumień utrzymania SSFV

```bash Features stream
qxctl knowledge session features begin
qxctl knowledge session features status
qxctl knowledge session features checkpoint
qxctl knowledge session features close
qxctl knowledge session features recover
```

Strumień features to oddzielny, trwały kontekst utrzymania SSFV. Mutacje wymagają:

- Otwartej, uwierzytelnionej sesji podstawowej
- Dokładnych wiązań koordynatora i SSFV
- Stabilnych identyfikatorów operacji
- Dokładnej operacji compare-and-swap
- Świeżych dowodów SSIAG

<Note>
  Zachowuj migawkę bazową i pierwotną tożsamość jej silnika w przypadku zgodnych aktualizacji lub wycofań. Opcjonalne dowody Maestro muszą stanowić kompletny, uwierzytelniony inwentarz; gdy Maestro jest celowo nieobecny, zapisz jawny powód braku konfiguracji. `review_required` to dowód do przeglądu przez wywołującego, a nie ratyfikacja.
</Note>
