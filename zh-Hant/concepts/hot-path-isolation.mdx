Symphony 將管理工作與執行工作分開，讓即時交易、研究及其他對效能敏感的路徑不受抖動、延遲與隱藏相依項影響。qxctl 與知識平面屬於冷路徑或凍結路徑的管理工作。它們可以明確地對同時承載即時工作的 Node 執行操作，但絕不能成為持續性的熱路徑相依項。

## 冷路徑與凍結路徑紀律

qxctl 與 vector 引擎是屬於冷路徑或凍結路徑的管理元件。它們不得：

- 與熱路徑或溫路徑執行內嵌執行
- 與即時工作負載共用鎖定
- 建立會增加抖動或延遲的同步相依項
- 成為隱藏的監看程式、常駐的直譯器，或未經要求的背景套件管理員
- 在執行用 Node 上持續常駐

此規則適用於知識工作階段協調器、vector 引擎，以及所有由 qxctl 管理的操作。它們會產生證據、驗證狀態並準備計畫，但不會參與即時執行路徑。

## 匯流排紀律

大量傳輸、控制、研究與執行輸出資料不必共用同一條匯流排。拓撲可以使用多條匯流排，或為已宣告的路徑略過匯流排，特別是在共用流量可能引入抖動的情況下。NATS JetStream、ZeroMQ 及其他架構都是轉接器與使用者的選擇。qxctl 具備匯流排管理功能，並不代表必須經過匯流排。

你可以選擇符合自身延遲與輸送量需求的匯流排拓撲。Symphony 支援該設定，而不會強制使用單一共用架構。

## Prima Parte

**Prima Parte** 是已批准的 Phase 3 概念，而非目前可執行的程式。它是一個選用、極度輕量的 C++ Node 本機狀態見證，在重大操作之後由 qxctl 明確呼叫。它沒有常駐程式、監聽器、計時器、監看程式、輪詢迴圈或常駐的匯流排連線。

其有界限的持久詞彙包含三個術語：

- `current`：目前觀測到的狀態
- `previous`：重大操作之前的狀態
- `lastTransmitted`：相關指令執行後，由遠端 Node 傳送的狀態（未確認已接收）

Prima Parte 只記錄它自己的 Node，絕不會變成縮小版的 Maestro，並在完成其有界限的工作後結束。它不是 Phase 1 的 Maestro 接收器，而且目前尚未實作任何可執行程式。
