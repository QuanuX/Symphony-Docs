Symphony 定義了三個實體概念，用以區分硬體身分、軟體配置與使用者工作負載。這些概念讓基礎架構的各項考量彼此分明，讓你可以分別獨立思考每一項。

## Node

**Node** 是具有明確識別資源的目標實體電腦資源。中斷連線、重新連線、重新啟動或僅重新燒錄軟體，並不會產生新的實體 Node。銷毀、實體更換或重大的本機硬體變更才會。Node 化身（incarnation）是另一項獨立的證據，在該 Node 作為交易系統、研究叢集或其他以 Symphony 建置的系統之參與者而連接到匯流排時建立。

## Habitat

**Habitat** 是針對你所選擇的工作，交付給 Node 的精確作業系統與套件配置。其預設僅包含必要的軟體範圍：沒有無關的套件、隱藏的執行環境、容器、Kubernetes 或隱含的虛擬化。廣泛的通用型 Habitat 仍是有效的明確使用者選擇。

## Nest

**Nest** 服務於你所選擇的用途。即時策略執行預期會是常見用途，而一個策略可能包含許多模組化的程式碼區段。Symphony 不會定義 Nest 的用途，也不會將其等同於單一原始碼檔案、程序、演算法、券商 API 或資料介面。策略邏輯始終屬於你的領域。

## 比較

| 概念 | 定義 | 變更條件 |
| --- | --- | --- |
| **Node** | 具有特定資源的實體電腦 | 實體銷毀、更換或重大硬體變更 |
| **Habitat** | Node 上精確的作業系統與套件配置 | 使用者明確選擇或由 qxctl 管理的配置 |
| **Nest** | 交付至 Habitat 中、服務使用者用途的工作負載 | 使用者部署策略或其他所選工作 |

## 叢集與匯流排拓撲

多個 Node 只有在透過一條或多條匯流排彼此連接時，才會形成叢集。一個叢集內可以同時存在多種匯流排架構，而 Node 與叢集之間的關係可以識別相關的匯流排，而不會改變實體 Node 的身分。

NATS JetStream 與 ZeroMQ 等匯流排轉接器由使用者選擇，而非準則規定。大量傳輸、控制、研究與執行輸出資料不必共用同一條匯流排。拓撲可以使用多條匯流排，或為已宣告的路徑略過匯流排。

## TOPS 與 TROG 範圍

**TOPS** 是主導的交易作業系統（Trade Operating System）範圍。**TROG** 是刻意設為從屬、非全域的交易群組範圍。儘管沿用了歷史上的用語，TROG 並不一定是虛擬的。它的區別特徵在於其範圍與規則並非通用。
