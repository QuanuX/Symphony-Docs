Symphony 的架構圍繞兩個概念組織：**vector** 是持久的語意所有權領域，而**階段（phase）**則是依時間順序進行的交付活動。某個元件最初在某個階段中研究，並不代表該階段就是它的永久擁有者。Vector 讓意義在實作演進的同時保持穩定。

## 什麼是 vector？

Vector 是一個持久且有界限的語意所有權領域，其標準合約擁有該領域的意義與允許的操作。每個 vector 都會獲得一組 **Contract Quad**：`INTENT.md`、`MANIFEST.md`、`SKILL.md` 與 `SPEC.md`，以及它實際需要的特定附屬介面。Vector 宣告其標準介面與委派圖，SKVI 會將每個現行介面精確對應一次。過時的附屬介面則透過受治理的演進予以取代，而不會作為相互矛盾的脈絡殘留下來。

## Contract Quad 與附屬介面

每個 vector 都會獲得：

1. **INTENT.md**：用途與範圍
2. **MANIFEST.md**：身分、已宣告的介面、委派圖
3. **SKILL.md**：安全使用與操作指引
4. **SPEC.md**：規範性行為與界線

`SLANG.md`、`NAMESPACES.md`、登錄檔、結構描述與設定檔等附屬介面，仍是四成員結構之外的受治理成品。它們會路由或特化擁有者的真相，但無法擴大自身的權限。

## 以證據為基礎的整合

延後的引擎沒有捏造的回執。提議中的 API 沒有虛構的登錄項目。未發布的合約沒有 SODV 完成聲明。這是以證據為基礎的整合，而非形式上的重複。
