Symphony 準則界定了平台所控制的範圍與你所控制的範圍之間的界線。這些規則約束 monorepo 中的每一項設計決策，以及與 qxctl、vector 引擎和知識合約的每一次互動。

## 使用者所有權

你擁有自己的策略邏輯、Nest 用途、供應商選擇、硬體選擇、匯流排拓撲，以及所支援轉接器的選擇。Symphony 提供精確的相容性證據與受支援的操作，但不會把建議變成平台的強制規定。平台會回報相符、不符、尚未解決的事實及其後果。它不會為供應商排名、不會規定策略，也不會悄悄擴大你的環境。

## 熱路徑保護

熱路徑受到保護，不受管理常駐程序與意外共用匯流排壓力的影響。qxctl 與知識平面屬於冷路徑或凍結路徑的管理工作。它們可以明確地對同時承載即時工作的 Node 執行操作，但絕不能成為持續性的熱路徑相依項、隱藏的監看程式、常駐的直譯器，或未經要求的背景套件管理員。你明確制定的架構始終具有最高主導權。

## 指令與語意分離

qxctl 擁有指令文法與呈現方式。各領域 vector 擁有這些指令所公開的操作及其意義。qxctl 路由會呼叫由擁有者定義的能力，而不會吸收其語意。

## 名稱與命名空間

名稱記錄在其所屬範圍之下。SNV 與 SCNV 不會指定名稱，而根層級的 NAMESPACES 範圍也比 SNV 更廣。在 TOPS 或 TROG 中註冊的名稱遵循該範圍。在多個叢集之中，同一個 Node 簡稱可以在不同叢集中重複出現，但不得在同一個叢集中含糊地識別兩個作用中的 Node。

## 呼叫者類別中立

呼叫者被分類為人類、AI、代理程式、服務或工作負載，並不會因此授予或移除權限。受支援的授權決策依據的是目標主機的所有權或已授予的權限、所請求的操作與資源、預期狀態，以及擁有者設定的防護措施。目標主機的管理員對可設定的治理擁有最高主導權。SSIAG 可以驗證並投影有效的主機權限，但不會建立更高層級的註冊權威。強化身分保證與治理連鎖機制是與呼叫者無關、由擁有者設定的防護措施。協定完整性要求仍屬強制。Symphony 不會依呼叫者類型決定外部的法律或財務行為能力。

## 真相與證據

現行合約描述現行的真相。不可變的 SCLV 與 SODV 記錄保存了在其記錄的歷史時間點上已知、已變更、已授權或已完成的內容。當現行合約、實作證據與最新適用記錄之間出現不一致時，該不一致會以漂移的形式呈現以供審查。歷史不會被悄悄改寫成與現狀相符。

## Python 準則

第一方 Symphony 原始碼、產生器、結構描述撰寫、測試與驗收輔助工具，不需要任何 Python 實作或直譯器相依項。由 C++ 負責替代的撰寫與程序測試工具。此儲存庫政策不會限制你自行撰寫的程式，或你明確選擇的隔離 Habitat。
