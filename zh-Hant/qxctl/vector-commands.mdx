qxctl 為每個已實作的 SKV 引擎以及 SCV 與 SHV 管理提供向量專屬語法。已批准的 Accordare 與 SEV 語法，將在其命令實作與穩定的登錄檔證據存在後，使用 `qxctl accord ...` 與 `qxctl evolution ...`。

## SKV 引擎語法

- `qxctl skvi ...`：針對 SKVI 引擎執行 inspect、check、propose、project
- `qxctl sclv ...`：針對 SCLV 引擎執行 inspect、check、propose、recover、project
- `qxctl sacv ...`：針對 SACV 引擎執行 inspect、check、diff、propose、project
- `qxctl sodv ...`：針對 SODV 引擎執行 inspect、check、verify、propose、recover、project
- `qxctl ssfv ...`：針對 SSFV 引擎執行 inspect、check、diff、propose、graph

每種語法都受所屬引擎的合約約束。qxctl 絕不會自行發明操作或繞過引擎。

## Accordare 新增功能

qxctl 上的 Accordare 新增功能提供：

- 穩定狀態
- 協調（僅重播確切的候選項目）
- Supervisor 安裝與解除安裝（僅呼叫經驗證的 receipt-v2 可執行檔）
- 兩個授權管理身分，僅在 SSIAG 與預期狀態復原下變更已停止的 STAV 設定

狀態會區分持久性意圖與附加待辦項目。協調只會重播確切的候選項目。授權葉節點命令絕不會開啟執行中的設定。

## SHV 儲存

持久性 SHV 儲存只能透過以下方式管理：

```bash SHV graph store
qxctl shv graph store inspect
qxctl shv graph store prepare
qxctl shv graph store commit    --expected-intent-digest DIGEST
qxctl shv graph store status
qxctl shv graph store query
qxctl shv graph store export
qxctl shv graph store schema
qxctl shv graph store template
```

帶有保留之預期意圖摘要的 `commit` 同時也是復原方式。沒有另外的復原別名。儲存範圍在輸入中宣告；連接器身分則在旗標中設定。結構性儲存不會重複語意性的 `shv graph validate`，也不會選擇目錄頭（catalogue head）。

`shv graph store inventory`（0.2 版）新增了與修訂版本綁定的邏輯讀取，並帶有明確保留的寫入者身分。舊版 0.1 的選擇方式仍受支援。

## SHV 目錄發布

目錄發布只能透過以下方式管理：

```bash SHV catalogue publication
qxctl shv catalogue publication inspect
qxctl shv catalogue publication plan
qxctl shv catalogue publication apply    --operation-id OPID
qxctl shv catalogue publication status
qxctl shv catalogue publication schema
qxctl shv catalogue publication template
```

復原方式為 `apply --operation-id`，與 `--input` 互斥。以權限為基礎的本機目錄選擇，有別於來源啟用與一般圖形儲存。
