Symphony Ops Vector（SOV）は、認可された qxctl コマンドがインフラストラクチャに対して動作するための運用コントロールプレーンです。プロビジョニング、Habitat のコンディショニング、Nest のデリバリー、バスアダプターのセットアップ、オプションのリモート Node 管理のコントラクトを所有します。SOV はプロバイダーの意味やハードウェアの事実を作り出すことはなく、あなたがすでに選択したサポート対象の選択肢を実行します。

## SOV がカバーする範囲

SOV は、新たな Phase 2 のドメインです。そのスコープには次のものが含まれます:

- **プロビジョニング**: プロバイダーおよび所有ハードウェアのリソース割り当てワークフロー
- **Habitat のコンディショニング**: Node に提供される正確な OS とパッケージのコンディショニング
- **Nest のデリバリー**: Node 上でのワークロードの配置と更新
- **バスアダプターの確立**: 選択したバス（NATS JetStream、ZeroMQ など）を通じた Node の接続
- **リモート Node の操作**: ローカルシェルの外にある Node のオプションの管理

<Note>
  プロバイダープロトコル、Terraform の実行、Habitat ビルダー、Nest のデプロイコマンド、リモート操作のレシーバーは、まだ設計されていません。SOV エンジンやプロバイダーの変更は、現在いずれも実装されていません。
</Note>

SOV はコントロールプレーンであり、知識のソースではありません。他のベクターが所有するエビデンスに基づいて動作します:

## コマンドサーフェスとしての qxctl

SOV の操作は、373 個の実行可能コマンドを持つ Go ベースの管理 CLI である `qxctl` を通じて公開されます。qxctl は SOV の操作を実装・提示しますが、そのドメイン上の意味は所有しません。セマンティクスはベクターが所有し、実行サーフェスはツールが所有します。

## ユーザー権限の境界

プロバイダー、リージョン、ハードウェア、バス、ソフトウェア、デプロイトポロジー、Node ごとの管理体制は、あなたが選択します。SOV はサポート対象の選択肢を公開し、実行します。プロバイダーをランク付けしたり、トポロジーを推奨したり、提案を必須のポリシーに変換したりはしません。

## 現在のステータス

SOV は正規のアーキテクチャコントラクトです。エンジン、Terraform ラッパー、Habitat ビルダー、バスアダプター、リモートコマンドレシーバーのいずれも、実装済みとはされていません。将来の SOV コンポーネントは、共通の SKV ライフサイクルのもとで、引き続き個別にインストール可能、正確なバージョンで選択可能、かつロールバック可能となります。
