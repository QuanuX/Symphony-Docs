`qxctl knowledge lifecycle ...` 文法は、保護されたプロファイル、所有権、観測、ブートジャーナル、apply 互換の遷移を管理します。すべての変更は compare-and-swap であり、すべての apply は正確なエビデンスに束縛されます。

## プロファイル

TOPS の保護されたライフサイクルプロファイルを設定します:

```bash Profile compare-and-swap
qxctl knowledge lifecycle profile set \
  --tops-id UUID \
  --input FILE \
  --expected-profile-digest absent|DIGEST
```

初めてのプロファイルには `absent` を、それ以外の場合は以前の読み取りで報告された正確なダイジェストを指定します。

## 所有権

- `ownership status`: 構成済みの共有ルートを 1 つ検査する
- `ownership reconcile`: そのエビデンスを更新する
- `ownership adopt`: すべての保守的なレガシークレームを確認した後にのみ採用する
- `ownership release`: 意図的に再取得可能にした 1 つの正確なレガシーレシートに対してのみ解放する

<Warning>
  ルートローカルのレジストリや、その `symphony-root-ownership/1` レシートレイアウト互換性フェンスを手動で削除したり書き換えたりしないでください。古いライフサイクルクライアントはそのフェンスに遭遇し、既存の unknown-package ブロッカーで停止する必要があります。
</Warning>

## observe、report、boot

- `observe`: 使い捨ての固定レイアウトのレシートエビデンスを出力する
- `report`: 新しい使い捨てのプランを生成する
- `boot`: 安定したオペレーション ID と正確なジャーナル状態を伴う、永続的な report 専用の進行
- `status`: v1 の検査
- `recover --discover`: 通常の status でローカル状態を検証できない場合に、一意の v1 チェーンを回復する

## apply 互換プロファイル

`apply-compatible` プロファイルでは、正確なブートソースダイジェスト、apply ジャーナルの compare-and-swap、適用済み状態の compare-and-swap、安定したオペレーション ID、明示的なステージングルートを指定した場合にのみ `apply` を呼び出します:

```bash Apply
qxctl knowledge lifecycle apply \
  --tops-id UUID \
  --operation-id OPID \
  --boot-source-digest DIGEST \
  --expected-apply-journal-digest DIGEST \
  --expected-applied-state-digest DIGEST \
  --staged-root PATH
```

試行の観測には `apply-status` を、永続的なリカバリーには範囲が限定された `apply-recover` を使用します。アクションを手動で選択したり、保護された状態を編集したりしないでください。

<Note>
  タイムスタンプのみの観測更新は、安定したセマンティック ID を進めることなく、ドキュメントのエビデンスを変更する必要があります。
</Note>
