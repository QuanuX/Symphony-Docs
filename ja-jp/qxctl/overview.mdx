`qxctl` は、Symphony の Go ベースでエージェントファーストな管理・クエリ CLI です。qxctl はコマンドを扱い、その背後にある操作と意味はドメインベクターが所有します。チェックインされたレジストリは、すべての実行可能コマンドリーフを、安定したマシン ID とレビュー済みの機能管理エビデンスにバインドします。

## qxctl がカバーする範囲

qxctl は次の管理を実装しています:

- リポジトリとコントラクトの検査
- バリデーター、警告、不変条件、機能、ライフサイクル、セッション、調整、バインディング、Maestro の管理
- SSIAG ID、STAV 監査、Accordare プロデューサーの管理
- 実装済みのベクターエンジン文法（`skvi`、`sclv`、`sacv`、`sodv`、`ssfv`、および SCV と SHV のサーフェス）

現在のレジストリには **373** 個の実行可能コマンドが含まれています。

## 安全な呼び出しモデル

qxctl は、範囲が限定されたサブプロセス、厳格なデッドライン、レスポンス ID とダイジェストのチェック、期待状態トランザクション、永続的なリカバリーを用いて、レシート検証済みの正確なインストールを呼び出します。レシートの代わりにアダプターパスや生のバージョンを受け付けることは決してありません。

## エンジンバインディングレジストリ v2

エンジンバインディングレジストリ v2 は、確立された 8 つのエンジンロールと、範囲が限定された将来のロール ID をサポートします。レガシーの v1 状態はデュアルリードされます。v2 への移行には qxctl を通じた明示的なダイジェスト束縛の compare-and-swap が必要であり、バージョン選択操作になることは決してありません。

## レジストリコマンド

`tools/qxctl` から期待されるレジストリを生成して検証します:

```bash Registry generation and verification
go run ./cmd/qxctl commands expected --json > COMMANDS.json
go run ./cmd/qxctl commands verify --input COMMANDS.json --json
```

インストール済みのクライアントは、実行ファイルに束縛されたエビデンスを出力できます:

```bash Manifest from installed qxctl
qxctl commands manifest --json
```

期待エビデンスでは、クライアントバージョン、実行ファイルダイジェスト、レシートダイジェストが null になります。観測エビデンスは、正確なクライアントバージョンと実行ファイルダイジェスト、および利用可能な場合はレシートダイジェストをバインドします。どちらの形式も `symphony.qxctl.command-registry.v1` を使用します。

<Note>
  qxctl はコマンド文法と表示を所有します。ベクターのセマンティクスや正規の知識の真実は所有しません。呼び出し元のクラスにかかわらず、新しい `qxcmd` ID を承認できるのはレビュー済みのソース変更のみです。
</Note>
