`qxctl knowledge session ...` 文法は、バインドされた 1 つの正確なコーディネーターと、TOPS スコープの 1 つの SSIAG エンドポイントを通じて、非正規の認証済みセッションを開きます。別の `session features ...` 文法が永続的な SSFV メンテナンスストリームを操作します。

## 基本セッション文法

```bash Session lifecycle
qxctl knowledge session begin
qxctl knowledge session status
qxctl knowledge session checkpoint
qxctl knowledge session close
qxctl knowledge session recover
```

すべての呼び出しは新しい正確なグラントを要求し、次の項目を検証します:

- サブジェクトとターゲットの ID
- ポリシーと構成の状態
- 有効期限
- 呼び出し元クラスの中立性
- 譲渡不可性
- 正規 apply の無効化
- ケイパビリティのバインディング

セッションエビデンスが認可するのは、指定された保護された非正規操作のみです。セッションジャーナルと調整ジャーナルは分離して保持し、それらの関連付けにはコンテキスト参照のみを使用してください。

## SSFV メンテナンスストリーム

```bash Features stream
qxctl knowledge session features begin
qxctl knowledge session features status
qxctl knowledge session features checkpoint
qxctl knowledge session features close
qxctl knowledge session features recover
```

features ストリームは、独立した永続的な SSFV メンテナンスコンテキストです。変更には次のものが必要です:

- 開かれている認証済みの基本セッション
- 正確なコーディネーターと SSFV のバインディング
- 安定したオペレーション識別子
- 正確な compare-and-swap
- 新しい SSIAG エビデンス

<Note>
  互換性のあるアップグレードやロールバックをまたいで、ベースラインスナップショットとその元のエンジン ID を保持してください。オプションの Maestro エビデンスは、完全な認証済みインベントリでなければなりません。Maestro が意図的に存在しない場合は、明示的な未構成の理由を記録してください。`review_required` は呼び出し元によるレビューのためのエビデンスであり、承認ではありません。
</Note>
