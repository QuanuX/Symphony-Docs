Symphony は、ハードウェアの識別情報、ソフトウェアのコンディショニング、ユーザーのワークロードを区別する 3 つの物理的な概念を定義します。これらの概念によってインフラストラクチャ上の関心事が分離されるため、それぞれを独立して検討できます。

## Node

**Node** は、具体的に識別されたリソースを持つ、ターゲットとなる物理コンピューターリソースです。切断、再接続、再起動、またはソフトウェアのみの再書き込みでは、新しい物理 Node は作成されません。破壊、物理的な交換、またはローカルハードウェアの重要な変更があった場合は、新しい Node になります。Node インカネーションは、その Node がトレーディングシステム、リサーチクラスター、またはその他の Symphony で構築されたシステムの参加者としてバスに接続されたときに作成される、別個のエビデンスです。

## Habitat

**Habitat** は、あなたが選択した作業のために Node に配信される、厳密なオペレーティングシステムとパッケージのコンディショニングです。デフォルトでは、必要なソフトウェアサーフェスのみで構成されます。無関係なパッケージ、隠れたランタイム、コンテナ、Kubernetes、暗黙的な仮想化は含まれません。幅広い汎用的な Habitat も、ユーザーの明示的な選択として引き続き有効です。

## Nest

**Nest** は、あなたが選択した目的を果たします。ライブ戦略の実行が一般的な用途として想定されており、1 つの戦略に多数のモジュール式コードセクションが含まれる場合もあります。Symphony は Nest の目的を定義したり、1 つのソースファイル、プロセス、アルゴリズム、ブローカー API、データインターフェースと同一視したりしません。戦略ロジックはあなたの領域です。

## 比較

| 概念 | 内容 | 変更のきっかけ |
| --- | --- | --- |
| **Node** | 特定のリソースを持つ物理コンピューター | 物理的な破壊、交換、またはハードウェアの重要な変更 |
| **Habitat** | Node 上の厳密な OS とパッケージのコンディショニング | ユーザーの明示的な選択、または qxctl が管理するコンディショニング |
| **Nest** | Habitat に配信されるユーザー目的のワークロード | ユーザーによる戦略またはその他の選択した作業のデプロイ |

## クラスターとバストポロジー

複数の Node は、1 つ以上のバスを通じて互いに接続されている場合にのみクラスターを形成します。1 つのクラスター内に複数のバスファブリックが共存でき、Node とクラスターの関係では、物理 Node の識別情報を変えることなく、該当するバスを識別できます。

NATS JetStream や ZeroMQ などのバスアダプターはユーザーが選択するものであり、ドクトリンではありません。大量転送、制御、リサーチ、実行の排出データは、1 つのバスを共有する必要はありません。トポロジーでは、複数のバスを使用したり、宣言されたパスでバスをバイパスしたりできます。

## TOPS と TROG のスコープ

**TOPS** は、支配的な Trade Operating System のスコープです。**TROG** は、意図的に従属させた、グローバルではないトレーディンググループのスコープです。歴史的な呼称とは異なり、TROG は必ずしも仮想的なものではありません。その特徴は、スコープとルールが普遍的ではないという点にあります。
