Maestro (`modules/maestro`) — это независимо устанавливаемый орган присутствия на C++26 для «замороженного» пути. Он фиксирует точные аутентифицированные отношения стыковки векторных движков для каждого TOPS и рецептора и формирует полную инвентаризацию только для чтения того, что пристыковано в данный момент. Maestro — свидетель, а не надзиратель.

## Что фиксирует Maestro

- Точные аутентифицированные отношения стыковки между векторными движками и рецепторами
- Разграничение по TOPS, чтобы присутствие каждой установки оставалось приватным для неё
- Производную полную инвентаризацию только для чтения, доступную через `qxctl maestro inventory`

## Чего Maestro не делает

<Warning>
  Maestro не запускает, не планирует, не надзирает и не вызывает движки. Привязка, согласование, координация аутентифицированных сессий или план жизненного цикла сами по себе не устанавливают присутствие в Maestro, не утверждают семантическую истину, не изменяют канонические знания и не доказывают полноту установленного хоста.
</Warning>

- Maestro не создаёт процессов.
- Maestro никогда не применяет изменения канонических знаний.
- Maestro никогда не заменяет векторный движок, владеющий семантикой.
