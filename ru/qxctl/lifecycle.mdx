Грамматика `qxctl knowledge lifecycle ...` администрирует защищённые профили, владение, наблюдения, журналы загрузки и совместимые с применением переходы. Каждая мутация выполняется как compare-and-swap, и каждое применение привязано к точным свидетельствам.

## Профиль

Задайте защищённый профиль жизненного цикла для TOPS:

```bash Profile compare-and-swap
qxctl knowledge lifecycle profile set \
  --tops-id UUID \
  --input FILE \
  --expected-profile-digest absent|DIGEST
```

Укажите `absent` для профиля, задаваемого впервые, или точный дайджест, полученный при предыдущем чтении.

## Владение

- `ownership status`: проверить один настроенный общий корень
- `ownership reconcile`: обновить его свидетельства
- `ownership adopt`: принять во владение только после проверки каждого консервативного унаследованного притязания
- `ownership release`: освободить только для одной точной унаследованной квитанции, намеренно сделанной доступной для повторного притязания

<Warning>
  Никогда не удаляйте и не переписывайте вручную локальный реестр корня или его барьер совместимости формата квитанций `symphony-root-ownership/1`. Более старые клиенты жизненного цикла должны натолкнуться на этот барьер и остановиться на своём существующем блокировщике неизвестного пакета.
</Warning>

## Наблюдение, отчёт, загрузка

- `observe`: выдать одноразовые свидетельства-квитанции фиксированного формата
- `report`: сформировать новый одноразовый план
- `boot`: долговременное продвижение только в режиме отчёта со стабильным идентификатором операции и точным состоянием журнала
- `status`: проверка v1
- `recover --discover`: восстановить уникальную цепочку v1, когда обычная команда status не может проверить локальное состояние

## Профили, совместимые с применением

Для профиля `apply-compatible` вызывайте `apply` только с точным дайджестом источника загрузки, compare-and-swap журнала применения, compare-and-swap применённого состояния, стабильным идентификатором операции и явно указанными подготовленными корнями:

```bash Apply
qxctl knowledge lifecycle apply \
  --tops-id UUID \
  --operation-id OPID \
  --boot-source-digest DIGEST \
  --expected-apply-journal-digest DIGEST \
  --expected-applied-state-digest DIGEST \
  --staged-root PATH
```

Используйте `apply-status` для наблюдения за попыткой или ограниченную команду `apply-recover` для долговременного восстановления. Никогда не выбирайте действие вручную и не редактируйте защищённое состояние.

<Note>
  Обновление наблюдения, затрагивающее только метку времени, должно изменять свидетельства документа, не продвигая стабильные семантические идентичности.
</Note>
