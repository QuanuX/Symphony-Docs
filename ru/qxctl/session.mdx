Грамматика `qxctl knowledge session ...` открывает неканонические аутентифицированные сеансы через один точный привязанный координатор и одну конечную точку SSIAG в области TOPS. Отдельная грамматика `session features ...` управляет постоянным потоком обслуживания SSFV.

## Базовая грамматика сеансов

```bash Session lifecycle
qxctl knowledge session begin
qxctl knowledge session status
qxctl knowledge session checkpoint
qxctl knowledge session close
qxctl knowledge session recover
```

Каждый вызов запрашивает новое точное разрешение (grant) и проверяет:

- Идентичность субъекта и цели
- Состояние политики и конфигурации
- Срок действия
- Нейтральность к классу вызывающей стороны
- Непередаваемость
- Отключение канонического применения
- Привязку возможностей

Свидетельства сеанса авторизуют только названную защищённую неканоническую операцию. Держите журналы сеансов и сверки раздельно; используйте ссылки на контекст только для их связывания.

## Поток обслуживания SSFV

```bash Features stream
qxctl knowledge session features begin
qxctl knowledge session features status
qxctl knowledge session features checkpoint
qxctl knowledge session features close
qxctl knowledge session features recover
```

Поток features — это отдельный постоянный контекст обслуживания SSFV. Мутации требуют:

- Открытого аутентифицированного базового сеанса
- Точных привязок координатора и SSFV
- Стабильных идентификаторов операций
- Точного compare-and-swap
- Свежих свидетельств SSIAG

<Note>
  Сохраняйте базовый снимок и исходную идентичность его движка при совместимых обновлениях или откатах. Необязательные свидетельства Maestro должны представлять собой полный аутентифицированный инвентарь; если Maestro намеренно отсутствует, зафиксируйте явную причину отсутствия конфигурации. `review_required` — это свидетельство для проверки вызывающей стороной, а не утверждение.
</Note>
