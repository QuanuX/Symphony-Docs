Грамматика `qxctl maestro ...` предоставляет свидетельства присутствия Maestro. Maestro — это орган присутствия; qxctl лишь читает и проверяет то, что фиксирует Maestro. Ни один из них не создаёт отношения стыковки самостоятельно.

## Инвентарь

```bash Maestro inventory
qxctl maestro inventory
```

`qxctl maestro inventory` представляет полный, производный, доступный только для чтения инвентарь Maestro аутентифицированных отношений стыковки векторных движков для каждого TOPS и рецептора.

## Связанные административные маршруты

Дополнительные листовые команды qxctl предоставляют администрирование, связанное с Maestro:

- Состояние и проверка свидетельств стыковки
- Маршруты восстановления, ограниченные собственными контрактами Maestro
- Базовая регистрация в жизненном цикле и нативный надзор для самого Maestro

Каждый маршрут мутации проходит через точный адаптер, принадлежащий модулю. qxctl никогда не формирует дескрипторы Maestro на основе внутреннего разбора и не вызывает неявно самую новую версию.

<Warning>
  Maestro не запускает, не планирует, не контролирует и не вызывает движки. `qxctl maestro inventory` работает только на чтение. Привязка, сверка, координация сеансов или план жизненного цикла сами по себе не устанавливают присутствие в Maestro.
</Warning>
