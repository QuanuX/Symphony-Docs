Symphony는 관리 작업을 실행 작업과 분리하여 실시간 거래, 연구, 기타 성능에 민감한 경로가 지터, 지연 시간, 숨겨진 의존성 없이 유지되도록 합니다. qxctl과 지식 플레인은 콜드 또는 프리징 패스 관리 구성 요소입니다. 실시간 작업도 호스팅하는 Node에 명시적으로 작업을 수행할 수는 있지만, 지속적인 핫 패스 의존성이 되어서는 안 됩니다.

## 콜드 및 프리징 패스 규율

qxctl과 vector 엔진은 관리용 콜드 또는 프리징 패스 구성 요소입니다. 이 구성 요소는 다음을 해서는 안 됩니다.

- 핫 또는 웜 실행 경로와 인라인으로 실행
- 실시간 워크로드와 잠금 공유
- 지터나 지연 시간을 추가하는 동기식 의존성 생성
- 숨겨진 감시자, 상주 인터프리터, 요청하지 않은 백그라운드 패키지 관리자가 되는 것
- 실행 Node에 지속적으로 상주

이 규칙은 지식 세션 코디네이터, vector 엔진, qxctl이 관리하는 모든 작업에 적용됩니다. 이들은 증거를 생성하고, 상태를 검증하고, 계획을 준비하지만, 실시간 실행 경로에는 참여하지 않습니다.

## 버스 규율

대용량 전송, 제어, 연구, 실행 배출 트래픽이 하나의 버스를 공유할 필요는 없습니다. 토폴로지는 특히 공유 트래픽이 지터를 유발할 수 있는 경우, 여러 버스를 사용하거나 선언된 경로에 대해 버스를 우회할 수 있습니다. NATS JetStream, ZeroMQ 및 기타 패브릭은 어댑터이자 사용자의 선택입니다. qxctl 버스 관리 기능이 있다고 해서 버스 경유가 필수가 되는 것은 아닙니다.

지연 시간과 처리량 요구 사항에 맞는 버스 토폴로지는 사용자가 선택합니다. Symphony는 단일 공유 패브릭을 강제하지 않고 해당 구성을 지원합니다.

## Prima Parte

**Prima Parte**는 비준된 Phase 3 개념이며, 현재 실행 파일은 아닙니다. 이는 중요한 작업 이후 qxctl이 명시적으로 호출하는, 선택적이고 매우 가벼운 C++ Node 로컬 상태 증인입니다. 데몬, 리스너, 타이머, 감시자, 폴링 루프, 상주 버스 연결이 없습니다.

경계가 정해진 내구성 어휘에는 세 가지 용어가 포함됩니다.

- `current` — 현재 관찰된 상태
- `previous` — 중요한 작업 이전의 상태
- `lastTransmitted` — 관련 명령이 실행된 후 원격 Node가 전송한 상태(수신 확인되지 않음)

Prima Parte는 자신의 Node만 기록하고, 더 작은 Maestro가 되지 않으며, 경계가 정해진 작업을 마친 후 종료됩니다. Phase 1 Maestro 수용체가 아니며, 아직 구현된 실행 파일은 없습니다.
