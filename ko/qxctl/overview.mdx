`qxctl`은 Symphony의 Go 기반, 에이전트 우선 관리 및 쿼리 CLI입니다. qxctl은 명령을 다루고, 그 뒤에 있는 작업과 의미는 도메인 벡터가 소유합니다. 체크인된 레지스트리는 모든 실행 가능한 명령 리프를 안정적인 머신 식별자와 검토된 기능 관리 증거에 바인딩합니다.

## qxctl이 다루는 범위

qxctl은 다음에 대한 관리 기능을 구현합니다.

- 저장소 및 계약 검사
- 검증기, 경고, 불변식, 기능, 수명 주기, 세션, 조정, 바인딩 및 Maestro 관리
- SSIAG 식별자, STAV 감사 및 Accordare 생산자 관리
- 구현된 벡터 엔진 문법(`skvi`, `sclv`, `sacv`, `sodv`, `ssfv` 및 SCV와 SHV 관련 기능)

현재 레지스트리에는 **373**개의 실행 가능한 명령이 있습니다.

## 안전한 호출 모델

qxctl은 범위가 제한된 하위 프로세스, 엄격한 마감 시간, 응답 식별자 및 다이제스트 검사, 예상 상태 트랜잭션, 영구 복구를 사용하여 정확한 영수증 검증 설치본을 호출합니다. 영수증 대신 어댑터 경로나 원시 버전을 절대 허용하지 않습니다.

## 엔진 바인딩 레지스트리 v2

엔진 바인딩 레지스트리 v2는 확립된 8개의 엔진 역할과 범위가 제한된 향후 역할 식별자를 지원합니다. 레거시 v1 상태는 이중 읽기되며, v2로의 마이그레이션에는 qxctl을 통한 명시적인 다이제스트 바인딩 compare-and-swap이 필요하고 절대 버전 선택 작업이 아닙니다.

## 레지스트리 명령

`tools/qxctl`에서 예상 레지스트리를 생성하고 검증합니다.

```bash Registry generation and verification
go run ./cmd/qxctl commands expected --json > COMMANDS.json
go run ./cmd/qxctl commands verify --input COMMANDS.json --json
```

설치된 클라이언트는 실행 파일에 바인딩된 증거를 출력할 수 있습니다.

```bash Manifest from installed qxctl
qxctl commands manifest --json
```

예상 증거에는 클라이언트 버전, 실행 파일 다이제스트, 영수증 다이제스트가 null입니다. 관찰 증거는 정확한 클라이언트 버전과 실행 파일 다이제스트를 바인딩하며, 가능한 경우 영수증 다이제스트도 바인딩합니다. 두 형식 모두 `symphony.qxctl.command-registry.v1`을 사용합니다.

<Note>
  qxctl은 명령 문법과 표현을 소유합니다. 벡터 의미나 정규 지식의 진실은 소유하지 않습니다. 호출자 클래스와 관계없이 검토된 소스 변경만이 새로운 `qxcmd` 식별자를 승인합니다.
</Note>
