`qxctl knowledge lifecycle ...` 문법은 보호된 프로필, 소유권, 관찰, 부팅 저널 및 apply 호환 전환을 관리합니다. 모든 변경은 compare-and-swap으로 수행되며 모든 apply는 정확한 증거에 바인딩됩니다.

## 프로필

TOPS에 대한 보호된 수명 주기 프로필을 설정합니다.

```bash Profile compare-and-swap
qxctl knowledge lifecycle profile set \
  --tops-id UUID \
  --input FILE \
  --expected-profile-digest absent|DIGEST
```

최초 프로필에는 `absent`를, 그렇지 않으면 이전 읽기에서 보고된 정확한 다이제스트를 제공하세요.

## 소유권

- `ownership status`: 구성된 공유 루트 하나를 검사합니다
- `ownership reconcile`: 해당 증거를 갱신합니다
- `ownership adopt`: 모든 보수적인 레거시 클레임을 검토한 후에만 채택합니다
- `ownership release`: 의도적으로 회수 가능하게 만든 정확한 레거시 영수증 하나에 대해서만 해제합니다

<Warning>
  루트 로컬 레지스트리나 그 `symphony-root-ownership/1` 영수증 레이아웃 호환성 펜스를 절대 직접 삭제하거나 다시 작성하지 마세요. 이전 수명 주기 클라이언트는 해당 펜스를 만나 기존의 unknown-package 차단 조건에서 멈춰야 합니다.
</Warning>

## Observe, report, boot

- `observe`: 일회용 고정 레이아웃 영수증 증거를 출력합니다
- `report`: 새로운 일회용 계획을 생성합니다
- `boot`: 안정적인 작업 ID와 정확한 저널 상태를 갖는 영구적인 보고 전용 진행
- `status`: v1 검사
- `recover --discover`: 일반 status로 로컬 상태를 검증할 수 없을 때 고유한 v1 체인을 복구합니다

## Apply 호환 프로필

`apply-compatible` 프로필의 경우, 정확한 부팅 소스 다이제스트, apply 저널 compare-and-swap, 적용 상태 compare-and-swap, 안정적인 작업 ID, 명시적인 스테이징 루트가 있을 때만 `apply`를 호출하세요.

```bash Apply
qxctl knowledge lifecycle apply \
  --tops-id UUID \
  --operation-id OPID \
  --boot-source-digest DIGEST \
  --expected-apply-journal-digest DIGEST \
  --expected-applied-state-digest DIGEST \
  --staged-root PATH
```

시도 관찰에는 `apply-status`를, 영구 복구에는 범위가 제한된 `apply-recover`를 사용하세요. 절대 작업을 수동으로 선택하거나 보호된 상태를 편집하지 마세요.

<Note>
  타임스탬프만 변경되는 관찰 갱신은 안정적인 의미 식별자를 진행시키지 않고 문서 증거만 변경해야 합니다.
</Note>
