Grammar `qxctl knowledge lifecycle ...` mengadministrasikan profil terlindungi, kepemilikan, observasi, jurnal boot, dan transisi yang kompatibel dengan apply. Setiap mutasi adalah compare-and-swap dan setiap apply terikat pada bukti yang persis.

## Profile

Tetapkan profil lifecycle terlindungi untuk sebuah TOPS:

```bash Profile compare-and-swap
qxctl knowledge lifecycle profile set \
  --tops-id UUID \
  --input FILE \
  --expected-profile-digest absent|DIGEST
```

Berikan `absent` untuk profil pertama kali atau digest persis yang dilaporkan oleh pembacaan sebelumnya.

## Ownership

- `ownership status`: memeriksa satu root bersama yang dikonfigurasi
- `ownership reconcile`: menyegarkan buktinya
- `ownership adopt`: mengadopsi hanya setelah meninjau setiap klaim legacy yang konservatif
- `ownership release`: melepaskan hanya untuk satu receipt legacy persis yang sengaja dibuat dapat diklaim ulang

<Warning>
  Jangan pernah menghapus atau menulis ulang registry root-local atau pagar kompatibilitas tata letak receipt `symphony-root-ownership/1` secara manual. Klien lifecycle yang lebih lama harus menemui pagar tersebut dan berhenti pada blocker unknown-package yang sudah ada.
</Warning>

## Observe, report, boot

- `observe`: menghasilkan bukti receipt sekali pakai dengan tata letak tetap
- `report`: menghasilkan rencana sekali pakai yang baru
- `boot`: progresi tahan lama yang hanya berupa laporan dengan ID operasi yang stabil dan state jurnal yang persis
- `status`: inspeksi v1
- `recover --discover`: memulihkan rantai v1 yang unik ketika status biasa tidak dapat memvalidasi state lokal

## Profil yang kompatibel dengan apply

Untuk profil `apply-compatible`, panggil `apply` hanya dengan digest sumber boot yang persis, compare-and-swap jurnal apply, compare-and-swap state yang diterapkan, ID operasi yang stabil, dan root staged yang eksplisit:

```bash Apply
qxctl knowledge lifecycle apply \
  --tops-id UUID \
  --operation-id OPID \
  --boot-source-digest DIGEST \
  --expected-apply-journal-digest DIGEST \
  --expected-applied-state-digest DIGEST \
  --staged-root PATH
```

Gunakan `apply-status` untuk observasi percobaan atau `apply-recover` yang terbatas untuk pemulihan tahan lama. Jangan pernah memilih tindakan secara manual atau mengedit state terlindungi.

<Note>
  Penyegaran observasi yang hanya mengubah timestamp harus mengubah bukti dokumen tanpa memajukan identitas semantik yang stabil.
</Note>
