A gramática `qxctl knowledge engines ...` gere o perfil de associação `default` protegido, no âmbito do utilizador, para os engines de vetores do Symphony. Associa conteúdo selecionado para reconciliação posterior. Não instala, invoca, ativa, acopla (dock), autentica, autoriza nem aplica um engine.

## Comandos

```bash Engines grammar
qxctl knowledge engines list
qxctl knowledge engines inspect
qxctl knowledge engines doctor
qxctl knowledge engines bind    --expected-registry-digest absent|DIGEST ...
qxctl knowledge engines unbind  --expected-registry-digest DIGEST ...
qxctl knowledge engines migrate --expected-registry-digest DIGEST ...
```

Indique `absent` para a primeira mutação do registo v2 ou o digest exato reportado por `list` para mutações posteriores. Cada mutação é uma operação compare-and-swap contra esse digest.

## Migração de v1 para v2

<Warning>
  O estado válido do registo v1 continua legível. A migração para v2 é uma operação compare-and-swap exata e separada, e nunca é uma operação de seleção de versão. Não trate a migração como um caminho de atualização para a seleção de engines.
</Warning>

- `list` e `inspect` continuam a funcionar sobre evidência v1.
- `migrate` produz uma geração v2 ligada sem descartar a verdade v1.
- Após a migração, utilize digests v2 para mutações futuras.

## O que é um bind

Um bind seleciona conteúdo exato para reconciliação posterior pelo coordenador. Um bind:

- Não instala um engine
- Não invoca nem ativa um engine
- Não acopla um engine ao Maestro
- Não autentica um chamador
- Não autoriza a aplicação (apply)
