`qxctl` Symphony का Go-आधारित, एजेंटिक-फ़र्स्ट प्रशासनिक और क्वेरी CLI है। यह कमांड बोलता है; उनके पीछे के ऑपरेशनों और अर्थों के स्वामी डोमेन वेक्टर हैं। इसकी चेक-इन की गई रजिस्ट्री हर निष्पादन योग्य कमांड लीफ़ को एक स्थिर मशीन पहचान और समीक्षित फ़ीचर-प्रशासन साक्ष्य से बाइंड करती है।

## qxctl किन चीज़ों को कवर करता है

qxctl निम्न के लिए प्रशासन लागू करता है:

- रिपॉज़िटरी और कॉन्ट्रैक्ट निरीक्षण
- वैलिडेटर, चेतावनी, इनवेरिएंट, फ़ीचर, लाइफ़साइकल, सेशन, रिकंसिलिएशन, बाइंडिंग और Maestro प्रशासन
- SSIAG पहचान, STAV ऑडिट और Accordare प्रोड्यूसर प्रशासन
- लागू किया गया वेक्टर-इंजन ग्रामर (`skvi`, `sclv`, `sacv`, `sodv`, `ssfv`, साथ ही SCV और SHV सतहें)

वर्तमान रजिस्ट्री में **373** निष्पादन योग्य कमांड हैं।

## सुरक्षित इनवोकेशन मॉडल

qxctl सीमित सबप्रोसेस, कठोर समय-सीमाएँ, रिस्पॉन्स पहचान और डाइजेस्ट जाँच, अपेक्षित-स्टेट ट्रांज़ैक्शन और टिकाऊ रिकवरी का उपयोग करके सटीक रसीद-मान्य इंस्टॉलेशन को इनवोक करता है। यह रसीदों के स्थान पर कभी भी एडैप्टर पथ या कच्चे संस्करण स्वीकार नहीं करता।

## इंजन-बाइंडिंग रजिस्ट्री v2

इंजन-बाइंडिंग रजिस्ट्री v2 आठ स्थापित इंजन भूमिकाओं और सीमित भविष्य की भूमिका पहचानों का समर्थन करती है। लेगेसी v1 स्टेट को दोहरे रूप से पढ़ा जाता है; v2 में माइग्रेशन के लिए qxctl के माध्यम से एक स्पष्ट डाइजेस्ट-बद्ध compare-and-swap आवश्यक है और यह कभी भी संस्करण-चयन ऑपरेशन नहीं है।

## रजिस्ट्री कमांड

`tools/qxctl` से अपेक्षित रजिस्ट्री जनरेट और सत्यापित करें:

```bash Registry generation and verification
go run ./cmd/qxctl commands expected --json > COMMANDS.json
go run ./cmd/qxctl commands verify --input COMMANDS.json --json
```

एक इंस्टॉल किया गया क्लाइंट निष्पादन-योग्य-बद्ध साक्ष्य उत्सर्जित कर सकता है:

```bash Manifest from installed qxctl
qxctl commands manifest --json
```

अपेक्षित साक्ष्य में क्लाइंट संस्करण, निष्पादन योग्य डाइजेस्ट और रसीद डाइजेस्ट null होते हैं। प्रेक्षित साक्ष्य सटीक क्लाइंट संस्करण और निष्पादन योग्य डाइजेस्ट को बाइंड करता है, और उपलब्ध होने पर रसीद डाइजेस्ट को भी। दोनों रूप `symphony.qxctl.command-registry.v1` का उपयोग करते हैं।

<Note>
  qxctl कमांड ग्रामर और प्रस्तुति का स्वामी है। यह वेक्टर सिमेंटिक्स या कैनॉनिकल ज्ञान सत्य का स्वामी नहीं है। कॉलर क्लास चाहे जो भी हो, केवल समीक्षित सोर्स परिवर्तन ही किसी नई `qxcmd` पहचान का अनुमोदन करते हैं।
</Note>
