在操作 Symphony 之前，请使用本指南熟悉整体情况。本文档将平台准则、用户选择的基础设施、vector 拥有的语义以及管理命令区分开来。确切的安装和执行步骤以相关组件的当前契约为准。

## 1. 阅读运行边界

从 [平台准则](/zh/doctrine) 开始。它确立了用户对策略和基础设施的所有权、调用方类别中立、基于证据的兼容性以及对热路径的保护。

## 2. 了解物理模型

阅读 [Node、Habitat 和 Nest](/zh/concepts/node-habitat-nest)：

- **Node：** 已标识的物理计算机资源。
- **Habitat：** 交付到 Node 上的精确操作系统和软件包配置。
- **Nest：** 放置到合适 Habitat 中、服务于用户用途的工作负载。

集群的总线和适配器是显式的架构选择。Symphony 不会规定通用的提供商或策略。

## 3. 追溯含义的所有权

[架构概览](/zh/concepts/architecture) 展示了 vector 契约、引擎、qxctl 与受治理证据之间的关系。[Vector 与阶段](/zh/concepts/vectors) 解释了为什么即使交付工作在各个阶段之间推进，vector 仍然是语义所有者。[Symphony Knowledge Vector](/zh/skv/overview) 介绍了 Contract Quad 及其配套表面。

## 4. 找到管理界面

[qxctl 概览](/zh/qxctl/overview) 介绍了基于 Go 的管理和查询 CLI。针对特定的命令族，请参阅 qxctl 相关页面，例如 [knowledge](/zh/qxctl/knowledge)、[lifecycle](/zh/qxctl/lifecycle)、[engines](/zh/qxctl/engines) 或 [validation](/zh/qxctl/validate)。qxctl 提供命令语法和呈现方式；vector 契约拥有操作及其含义。

## 5. 检查相关契约和证据

在对 Node 执行操作或调用 vector 引擎之前，请检查当前的所有者契约、目标状态、授权以及可用的回执或验证证据。[调用方权限](/zh/concepts/caller-authority) 和 [热路径隔离](/zh/concepts/hot-path-isolation) 解释了这些边界。新兴的表面并不构成隐含的运行保证。
