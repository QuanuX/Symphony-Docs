`qxctl knowledge lifecycle ...` 语法用于管理受保护的配置、所有权、观察、启动日志以及兼容 apply 的转换。每一次变更都采用比较并交换（compare-and-swap），每一次 apply 都绑定到确切的证据。

## 配置（Profile）

为某个 TOPS 设置受保护的生命周期配置：

```bash Profile compare-and-swap
qxctl knowledge lifecycle profile set \
  --tops-id UUID \
  --input FILE \
  --expected-profile-digest absent|DIGEST
```

首次设置配置时请提供 `absent`，否则提供之前读取时报告的确切摘要。

## 所有权

- `ownership status`：检查一个已配置的共享根目录
- `ownership reconcile`：刷新其证据
- `ownership adopt`：仅在审查完每一项保守的遗留声明后才接管
- `ownership release`：仅针对某一个被有意设为可回收的确切遗留回执进行释放

<Warning>
  切勿手动删除或改写根目录本地注册表或其 `symphony-root-ownership/1` 回执布局兼容性屏障。旧版生命周期客户端必须遇到该屏障，并在其现有的未知包阻断处停止。
</Warning>

## 观察、报告、启动

- `observe`：输出一次性的固定布局回执证据
- `report`：生成一份全新的一次性计划
- `boot`：持久化的仅报告推进，带有稳定的操作 ID 和确切的日志状态
- `status`：v1 检查
- `recover --discover`：当常规 status 无法验证本地状态时，恢复唯一的 v1 链

## 兼容 apply 的配置

对于 `apply-compatible` 配置，仅在具备确切的启动源摘要、apply 日志比较并交换、已应用状态比较并交换、稳定的操作 ID 以及显式的暂存根目录时才调用 `apply`：

```bash Apply
qxctl knowledge lifecycle apply \
  --tops-id UUID \
  --operation-id OPID \
  --boot-source-digest DIGEST \
  --expected-apply-journal-digest DIGEST \
  --expected-applied-state-digest DIGEST \
  --staged-root PATH
```

使用 `apply-status` 观察尝试情况，或使用有边界的 `apply-recover` 进行持久化恢复。切勿手动选择操作或编辑受保护状态。

<Note>
  仅涉及时间戳的观察刷新必须改变文档证据，而不能推进稳定的语义标识。
</Note>
