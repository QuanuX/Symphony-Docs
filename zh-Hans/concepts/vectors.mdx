Symphony 的架构围绕两个概念组织：**vector** 是持久的语义所有权领域，**阶段（phase）** 是按时间顺序推进的交付活动。某个组件最初在某一阶段中被研究，并不意味着该阶段就是它的永久所有者。Vector 使含义保持稳定，而实现则不断演进。

## 什么是 vector？

Vector 是一个持久的、有界的语义所有权领域，其规范契约拥有该领域的含义和允许的操作。每个 vector 都有一个 **Contract Quad**：`INTENT.md`、`MANIFEST.md`、`SKILL.md` 和 `SPEC.md`，以及它实际需要的专门配套表面。Vector 声明其规范表面和委派图，SKVI 将每个当前表面恰好映射一次，过时的配套表面则通过受治理的演进被取代，而不是作为相互矛盾的上下文残留下来。

## Contract Quad 与配套表面

每个 vector 都包含：

1. **INTENT.md** — 用途和范围
2. **MANIFEST.md** — 标识、声明的表面、委派图
3. **SKILL.md** — 安全使用和操作指南
4. **SPEC.md** — 规范性行为和边界

`SLANG.md`、`NAMESPACES.md`、注册表、schema 和配置文件等配套表面，仍是四成员结构之外的受治理工件。它们路由或细化所有者的事实，但不能扩大自身的权限。

## 基于证据的集成

延迟的引擎没有伪造的回执。提议的 API 没有虚构的注册表条目。未发布的契约没有 SODV 完成声明。这是基于证据的集成，而不是形式上的重复。
