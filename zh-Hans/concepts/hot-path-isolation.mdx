Symphony 将管理工作与执行工作分离，使实时交易、研究以及其他对性能敏感的路径免受抖动、延迟和隐藏依赖的影响。qxctl 和知识平面属于冷路径或冻结路径管理。它们可以显式地操作同时承载实时工作的 Node，但绝不能成为持续的热路径依赖。

## 冷路径与冻结路径规范

qxctl 和 vector 引擎是管理用的冷路径或冻结路径组件。它们不得：

- 与热执行路径或温执行路径内联执行
- 与实时工作负载共享锁
- 创建会增加抖动或延迟的同步依赖
- 成为隐藏的监视器、常驻解释器或未经请求的后台包管理器
- 在执行 Node 上保持持续常驻

此规则适用于知识会话协调器、vector 引擎以及所有由 qxctl 管理的操作。它们生成证据、校验状态并准备计划，但不参与实时执行路径。

## 总线规范

大量数据传输、控制、研究和执行产生的输出不必共享同一条总线。拓扑可以使用多条总线，也可以为某条已声明的路径绕过总线，尤其是在共享流量可能引入抖动的情况下。NATS JetStream、ZeroMQ 和其他总线结构都是适配器，由用户选择。qxctl 提供总线管理功能，并不意味着必须经由总线传输。

你可以选择符合自身延迟和吞吐量要求的总线拓扑。Symphony 支持该配置，而不会强加单一的共享总线结构。

## Prima Parte

**Prima Parte** 是一个已获批准的 Phase 3 概念，而不是当前可执行的程序。它是一个可选的、极其轻量的 C++ Node 本地状态见证，由 qxctl 在执行重要操作后显式调用。它没有守护进程、监听器、定时器、监视器、轮询循环或常驻总线连接。

其有界的持久词汇包括三个术语：

- `current` — 当前观测到的状态
- `previous` — 重要操作之前的状态
- `lastTransmitted` — 关联命令执行后由远程 Node 发送的状态（未确认已接收）

Prima Parte 只记录其自身所在的 Node，绝不会成为一个更小的 Maestro，并在完成其有界工作后退出。它不是 Phase 1 的 Maestro 接收器，目前也尚未实现任何可执行程序。
