Symphony 定义了三个物理概念，用于区分硬件身份、软件调配和用户工作负载。这些概念使各类基础设施关注点相互独立，便于你分别进行推理。

## Node

**Node**（节点）是具有特定标识资源的目标物理计算机资源。断开连接、重新连接、重启或仅重新刷写软件，都不会产生新的物理 Node。销毁、物理更换或重大的本地硬件变更则会产生新的 Node。Node 化身（incarnation）是一项单独的证据，在该 Node 作为交易系统、研究集群或其他基于 Symphony 构建的系统的参与者接入总线时创建。

## Habitat

**Habitat**（栖息环境）是为你所选工作交付给 Node 的确切操作系统和软件包调配。其默认值仅包含所需的软件表面：没有无关的软件包、隐藏的运行时、容器、Kubernetes 或隐式虚拟化。宽泛的通用型 Habitat 仍然是有效的显式用户选择。

## Nest

**Nest**（巢）服务于你所选择的用途。实时策略执行预计会很常见，一个策略可能包含许多模块化代码段，但 Symphony 不会定义 Nest 的用途，也不会将其等同于某个源文件、进程、算法、经纪商 API 或数据接口。策略逻辑始终属于你的领域。

## 对比

| 概念 | 是什么 | 什么会改变它 |
| --- | --- | --- |
| **Node** | 具有特定资源的物理计算机 | 物理销毁、更换或重大硬件变更 |
| **Habitat** | Node 上确切的操作系统和软件包调配 | 显式的用户选择或由 qxctl 管理的调配 |
| **Nest** | 交付到 Habitat 中的用户用途工作负载 | 用户部署策略或其他所选工作 |

## 集群与总线拓扑

只有当多个 Node 通过一条或多条总线相互连接时，它们才构成集群。一个集群内可以共存多种总线结构，Node 与集群之间的关系可以标识相关总线，而不会改变物理 Node 的身份。

NATS JetStream 和 ZeroMQ 等总线适配器由用户选择，而非准则规定。大规模传输、控制、研究和执行产出的数据不必共享同一条总线。拓扑可以使用多条总线，也可以为已声明的路径绕过总线。

## TOPS 与 TROG 作用域

**TOPS** 是占主导地位的交易操作系统（Trade Operating System）作用域。**TROG** 是一个有意设为从属的、非全局的交易组作用域。尽管历史措辞如此，TROG 并不一定是虚拟的。它的区别性特征在于其作用域和规则并非通用。
