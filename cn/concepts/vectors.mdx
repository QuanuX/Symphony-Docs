Symphony 的架构围绕两个理念组织：**vector** 是持久的语义所有权领域，**阶段**（phase）是按时间顺序进行的交付活动。某个组件最初在某一阶段中研究，并不意味着该阶段是它的永久所有者。Vector 在实现不断演进的同时保持含义稳定。

## 什么是 vector？

Vector 是一个持久的、有界的语义所有权领域，其规范契约拥有该领域的含义和允许的操作。每个 vector 都有一个 **Contract Quad**：`INTENT.md`、`MANIFEST.md`、`SKILL.md` 和 `SPEC.md`，外加它实际需要的专门配套表面。Vector 声明其规范表面和委托图，SKVI 将每个当前表面恰好映射一次，过时的配套表面会通过受治理的演进被取代，而不会作为相互矛盾的上下文残留下来。

## Contract Quad 与配套表面

每个 vector 都包含：

1. **INTENT.md** — 用途和范围
2. **MANIFEST.md** — 标识、声明的表面、委托图
3. **SKILL.md** — 安全使用和运维指南
4. **SPEC.md** — 规范性行为和边界

`SLANG.md`、`NAMESPACES.md`、注册表、schema 和配置文件等配套表面，仍是四成员结构之外的受治理工件。它们路由或细化所有者的事实，但不能扩展自身的权限。

## 基于证据的集成

延迟的引擎没有伪造的回执。提议中的 API 没有虚构的注册表条目。未发布的契约没有 SODV 完成声明。这是基于证据的集成，而不是形式上的重复。
