`qxctl` 是 Symphony 基于 Go、以智能体优先的管理与查询 CLI。它负责表达命令；其背后的操作与含义则由各领域向量拥有。其签入的注册表将每个可执行命令叶绑定到一个稳定的机器标识以及经过审查的功能管理证据。

## qxctl 涵盖的内容

qxctl 实现了以下方面的管理：

- 仓库与契约检查
- 验证器、警告、不变量、功能、生命周期、会话、协调、绑定以及 Maestro 管理
- SSIAG 身份、STAV 审计以及 Accordare 生产者管理
- 已实现的向量引擎语法（`skvi`、`sclv`、`sacv`、`sodv`、`ssfv`，以及 SCV 和 SHV 界面）

当前注册表包含 **373** 个可执行命令。

## 安全调用模型

qxctl 通过有界子进程、硬性截止时间、响应身份与摘要检查、预期状态事务以及持久化恢复，来调用经过回执验证的确切安装。它从不接受以适配器路径或原始版本号代替回执。

## 引擎绑定注册表 v2

引擎绑定注册表 v2 支持八种既定的引擎角色以及有界的未来角色标识。遗留的 v1 状态支持双读；迁移到 v2 需要通过 qxctl 执行显式的、绑定摘要的比较并交换，且绝不是版本选择操作。

## 注册表命令

在 `tools/qxctl` 中生成并验证预期注册表：

```bash Registry generation and verification
go run ./cmd/qxctl commands expected --json > COMMANDS.json
go run ./cmd/qxctl commands verify --input COMMANDS.json --json
```

已安装的客户端可以输出与可执行文件绑定的证据：

```bash Manifest from installed qxctl
qxctl commands manifest --json
```

预期证据中的客户端版本、可执行文件摘要和回执摘要均为 null。观察到的证据会绑定确切的客户端版本和可执行文件摘要，并在可用时绑定回执摘要。两种形式都使用 `symphony.qxctl.command-registry.v1`。

<Note>
  qxctl 拥有命令语法和呈现方式。它不拥有向量语义或规范知识事实。无论调用方类别如何，只有经过审查的源代码变更才能批准新的 `qxcmd` 标识。
</Note>
