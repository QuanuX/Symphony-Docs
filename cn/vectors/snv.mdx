Symphony Node 向量（Symphony Node Vector，SNV）记录并关联你在 Symphony 中使用的物理 Node（节点）的身份、资源、集群成员关系和名称。它由四个子向量组成，每个子向量拥有一个独立的语义边界。SNV 不会代表你选择、签发、规定或自动重命名任何内容。

## 子向量组成

SNV 由四个持久的语义领域构成：

<CardGroup cols={2}>
  <Card title="SNIV" icon="fingerprint">
    **Node 身份**：物理 Node 身份及其与确切的提供商资源、所选产品和基础设施域的关联。
  </Card>

  <Card title="SNRV" icon="gauge">
    **Node 资源**：Node 的本地资源事实以及明确限定的远程资源事实。
  </Card>

  <Card title="SCIV" icon="network-wired">
    **集群身份**：集群身份、总线连接以及 Node 与集群之间的关系。
  </Card>

  <Card title="SCNV" icon="tag">
    **统一命名**：在 SNV 范围内解析由你或你的提供商已分配的名称。
  </Card>
</CardGroup>

## 记录边界

SNV 记录事实及其沿袭。它不会为你预留名称、分配资源或创建集群。名称由用户分配，Symphony 负责记录；提供商资源由用户选择，Symphony 负责关联；集群拓扑由用户设计，Symphony 负责记载。

## 当前状态

SNV 是一份新兴的规范架构契约。目前尚未实现任何 SNV 引擎、图、注册表模式、身份编码器、发现服务、命名服务或 qxctl 命令。记录模式和引擎仍处于延后状态。

## 未来的可安装性

任何未来的 SNV 引擎都必须可独立安装，并能够根据确切的所有者证据重建其投影。任何引擎都不会仅因存储或解析记录而成为身份或命名权威。
